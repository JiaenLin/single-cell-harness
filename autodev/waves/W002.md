*The change, with no kernel diff:*
- `setup/locks/<platform>/<members>.txt`: one lock per group and platform, written by a new
  `scprofile lock <kernel> --platform TAG` (uv pip compile of the merged ranges plus
  `setup/locks/constraints.txt`). Its header records the members, platform, Python, resolver, the
  ranges it was resolved from, and their digest.
- `Group.name` hashes the lock's pins (with platform, Python, conda, channels, r) when a current lock
  exists for this machine; otherwise it hashes the ranges, as before.
- `install`: when locked, `pip install --no-deps -r` the exact pins (no resolve), then check every
  installed version against the lock, then write `.scprofile_resolved.txt` (pip and conda) beside the
  environment. If a lock for this platform no longer matches the ranges, install refuses to build from
  ranges and names what changed and the `scprofile lock` command. With no lock for this platform, install
  uses the ranges as before and says UNLOCKED. `doctor` and `install --dry-run` name the lock state.
- A new suite fails on `f294c89`. A separate first commit carries `48aaeba`'s five test and doc hunks
  (the matplotlib 3.11 renderer fix and GAP-051's four leak strings), so the gate is green on a fresh env.
- Jobs, authored and not submitted: (a) a fresh-prefix build of the group from the lock, then
  `scprofile selftest`; (b) the cellchat reproduction against `20260906T120759Z__scprofile-de199d0`,
  with the 90 tables compared byte for byte. Predictions as above.
