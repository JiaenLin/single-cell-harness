The change:
1. `scanno/assay.py`, one declared table. It holds the two assays (`scrna`, `snrna`; `sc` and `sn`
   accepted as this tool's original spellings, so SAMBO's store and jobs stay valid), the unit
   words for each, and the rule table: which rules depend on the assay and which do not, with
   where each was calibrated. A value is recorded as declared, so the store's bytes and digest do
   not change, and is compared canonically. An absent or unknown assay raises. There is no
   default.
2. The refusal. `annotate --store` refuses, by name, a store whose recorded assay differs from
   `--assay`, and a store that records none. `annotate` records its context in
   `uns["scanno_context"]`, and refuses an object already annotated under the other assay.
3. Wording. Every annotate print and both reports (`annotate --report` and `scanno report`) take
   their unit words from the assay. `scanno report` reads the assay from the objects' record;
   `--assay` is needed only when they carry none, and a contradiction is refused. Commands with no
   assay (cluster, scope, compare, rescue, help texts, describe) get neutral words. The agent
   prompt requires the assay: no `assay=""` read as cells.
4. Documentation. Every `scanno` command in README.md and docs/QUICKSTART.md is made runnable as
   written. Each false statement is fixed: README:42 (`--split-by` needs `--out-dir`; also
   refused before the work, not after the first piece), :44 (no column `leiden`), :197 (gap is the
   last step's margin: the declined one on a truncated call, `force.py:290`), :209 (a call with no
   decision gets gap 0.0 at `classify.py:144`; fixed in the code to NaN, the tool's own stated
   rule), QUICKSTART:58-60 (any pattern matches, order is irrelevant, and patterns must be lower
   case: `corpus.py:142`), :102 (var is re-keyed by symbol by default), the stale KNOWN_ISSUES
   step line, `corpus.py:5-8` (no `build-markers`), `cli.py:3-5` ("no report"). The USER_GUIDE
   gets the rule table.
