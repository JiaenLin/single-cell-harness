### 1. How scQC's stage maps onto the stack
- **Observations are the libraries at the stack's floor, declared as a parts manifest.** The kernel
  takes one observation file (sch/kernel.py:45-52, services/dataset.py:217-246), and no cohort
  arrives as one file: SAMBO is ten libraries, and the profile already says barcodes are unique only
  within `{sample}` (single-cell.yml `identity.scope`) without the kernel implementing it. So a stack
  may declare `observations: <manifest>` with `observation_parts: <column>`: one row per library, the
  scope column is the stack's `{sample}` key, and the parts column names the file holding that
  library's droplets. For a QC stage the manifest IS the tool's own samplesheet, as delivered; nothing
  is written for the harness. An observation's identity is `<sample>|<barcode>`: the profile's rule,
  joined the way scQC's own removal ledger joins it (engine/steps.py:2329), with the joiner declared
  in the profile (`identity.joiner`), not in code. The kernel reads each part's barcodes through h5py
  (no matrix is loaded), digests the manifest and every part (D2's witness; A1 re-checks after every
  plugin run), and materialises a parts stack as an identity-level view (`view.csv`: identity, scope,
  columns, keep, masks). Matrices stay in their parts, read in place; nothing copies a library.
- **The removal is masks, one per criterion.** scQC's step 7 is its only removing step, and its
  per-cell tables pair every barcode with each criterion's verdict (`fail_*` columns,
  adapters/scanpy_ops.py:3166-3195). The adapter contributes one WHOLE mask per criterion (ROADMAP
  Phase 3's "declares fine": each separately addressable while mounting as one plugin). Their fold is
  scQC's own `keep`, and the companion asserts it. `layer: stack`, `reversible: true`, tested at mount
  (E4). Unmounting restores every observation, because the observations were never written (D2/D4).
- **Ambient correction is a checkpoint** (D1, D5; scQC's own declaration, engine/declare.py:97). The
  stack's floor is that checkpoint, rebuilt upstream and supplied (the samplesheet's `ambient_h5`:
  SAMBO's route, copied verbatim by scQC, steps.py:342-376), or the aligner's call on single cells. The
  harness adopts the floor as its observations and does not run it in this wave. If scQC denoised a
  library inside the mount, its per-cell universe would no longer be the observations, and the
  kernel's merge-by-identity refuses that mount with both counts. An ambient checkpoint plugin needs
  an ambient-only entry in scQC's CLI, which is an open item.

### 2. What the adapter declares
`plugins/single-cell/qc@scqc/`: class `method`, `layer: stack`, `reversible: true`,
`state_version: 1` = scQC's `STATE_VERSION`. `scqc describe` is checked before any compute, and a
mismatch refuses, so the fold cache (D6) cannot serve numbers scQC changed. `needs:
[observations/raw]`: it reads the delivered parts itself, so it refuses a view with anything masked
beneath it. `provides: mask/fail_*`, the seven measured columns, `table/*`, `object/*`. `sees:
[design]`. `wraps:` scQC 0.4.0, MIT. Gates: the profile's `differential_check` (required on masks).
Its companion (invariant.py): the masks' fold equals scQC's `keep`, and the masked identities are
exactly scQC's removal ledger. Params: `scqc` (the CLI's path) and `registry` (the project's own) are
required, with no default. Every other scQC `run` flag is forwarded by name, in scQC's parser order.
An unknown name is refused, and an absent one is left to scQC's own default. `--project` (the
plugin's out_dir) and `--samplesheet` (the stack's manifest) are the adapter's, and are refused as
params.

**Rule 2.** The adapter refuses unless the stack declares `assay` in `profile_context`. It also
refuses when any library's samplesheet `assay` is empty or differs from it (strip/lower, as scQC
normalises). Every other declared axis that the samplesheet also carries must agree. Nothing is
filled in.

### 3. How the stage record is adopted
After `scqc run`, the adapter reads scQC's own `STATUS.json` and seal from `results/<digest>/`. There
is exactly one digest, because the project directory is fresh.
- `ok`, `SEALED.txt` and exit 0: the masks are contributed. `wrapped_versions` carries scQC's version
  and commit. `answer` carries the record: status, seal, headline, digest, argv and escapes.
- `refused` (exit 2, `FAILED.txt`): the mount is refused with scQC's reason and fix.
- `failed`, `partial`, no `STATUS.json`, or a seal that disagrees with the exit: no `out.json`, so
  the plugin died, and stderr quotes STATUS's headline.

Tables and objects are referenced in place under `out_dir/scqc/results/<digest>/`. That is scQC's
own layout, never copied or reshaped.

### 4. The `pbs` executor (no site literal)
`executor: pbs` reads a `pbs:` block from the stack declaration: the site layer
(`$SCH_SITE/stack.yml`) or the project. `queue`, `select` and `walltime` are required. `account` is
optional. `plugins.<name>` holds overrides, and `commands` holds qsub, qstat and qdel (from PATH unless
declared). A missing key is refused before any qsub, and the refusal names the fix.

For each plugin run, the kernel has already made the run directory. The executor then:
1. makes `<run>/pbs/` with a bare mkdir, so a collision aborts;
2. writes `job.pbs`: `set -euo pipefail`, `-o` into `pbs/`, the job's output appended to the run's
   log by `exec`, and an EXIT trap that writes `SEALED.txt` or `FAILED.txt` with the exit status,
   jobid, host, time and any missing product;
3. calls `qsub`. A queue-limit refusal waits, with backoff (scQC's lesson, ADR-0027 Q11);
4. polls `qstat` with backoff until the job finishes.

The exit status comes from the job's seal, then from qstat's `Exit_status`. If neither exists, the
outcome is unknown, which counts as died and never as 0. A timeout or unmount calls `qdel` and
confirms through qstat. If the stop cannot be confirmed, `stopped` is false and E5 fails the
unmount.

The kernel itself runs inside a job (rule 3). In the SAMBO job it stays local inside its job, the
compliant form. scQC gets `--executor pbs --queue short` as declared params, so its argv is job 30's
except `--project`.

A plugin's run directory name keeps `[A-Za-z0-9._-]` only, so `qc@scqc` runs in `plugins/qc_scqc/`.
Its paths reach scQC's own `#PBS -o` lines, and no `@` is put in front of a scheduler. Two names that
would share a directory are refused.
