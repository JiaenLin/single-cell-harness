# W016 (HARN/PROF): one plugin format, and a catalogue an agent can read

**Registered** 2026-11-09 by the coordinator, before any code or number. **Gaps** GAP-006, GAP-005.
**Goals** A4.4, A4.1, PROF.1, HARN.2. **Repository** single-cell-harness, base `main` = `c19802e`,
branch `autodev/W016-catalogue`. scProfile is read only, at `main` = `f5175ea`. W013 is on a branch
there; the catalogue must also read the layout the maker emits.

**Why now.** A4.1, A4.2 and A4.4 all FAIL at pass 0002. Each needs one thing first: a single plugin
format, and a catalogue an agent can list. GAP-046 (the maker on drawn tools), GAP-049 (self-assembly)
and GAP-012 (the co-scientist) all depend on GAP-005. GAP-006 is a design decision the pre-decider
gave to a design wave (gaps.tsv, its blocked_by). It is not the PI's: RULES tier II. The coordinator
adopts it, and reports it to the PI.

## The change
- **GAP-006: an ADR, "one plugin format".** Compare, field by field in a mapping table:
  - the harness's `plugin.yml` directory contract (PLUGIN_FORMAT.md, docs/AUTHORING.md);
  - scProfile's one-file `PLUGIN` dict (scprofile/kernels.py);
  - the layout the maker emits (cellchat).

  Adopt ONE as the Universal Plugin Format, or state precisely how one maps onto the other with
  nothing lost. Name what is given up. The ADR amends ADR-0004 and ROADMAP Phase 6 where they
  disagree. It moves no code between repositories; any migration is a later wave.
- **GAP-005: `sch catalogue`.** It lists every plugin the family has: the harness's own, and
  scProfile's, read from a scProfile checkout named by a flag. It does not import a tool's
  environment. Each row gives:
  - the id, and the question the plugin answers;
  - the inputs it requires: assay, design factors, layers;
  - its outputs;
  - its method provenance: upstream, exact version and DOI where declared, and `not declared`
    otherwise;
  - its format: the adopted one, legacy, or maker layout;
  - whether it has run on a cohort, from records the tool keeps, or `unknown`.

  It takes `--json` for agents and `show <id>` for one plugin. A plugin it cannot read is an error
  that names the file, never a silent drop (compare GAP-101).

**The format I expect to adopt: the maker's layout** (ADR-0030, the next free number on main and
on every `origin/autodev/*` branch). That is scProfile's one-file shape: `<name>.py`, whose
module-level `PLUGIN = {...}` literal is the declaration, read with `ast.literal_eval` and never
imported by a host or a catalogue. The maker's generated companions sit beside it, named
`<name>.<what>`. Why:
- GOALS defines the Universal Plugin Format by the maker. PROF.1 is "a plugin in the Universal
  Plugin Format"; A4.1 is "in the maker's layout".
- The maker emits this shape, and all nine plugins that wrap a published method are in it. No
  published-method plugin is a `plugin.yml` directory: the harness's 12 are kernel probes, gates,
  toys and one mask.
- Adopting `plugin.yml` would mean re-targeting the maker and re-declaring nine plugins. That is
  either a hand edit (tier II forbids it) or a maker re-fit that spends held-out evidence.
- No ARCHITECTURE invariant needs the directory. L3 holds because the declaration is read
  statically and the plugin runs as a subprocess. C4 holds because the boundary is in.json/out.json.

The schema is scProfile's api 1. The directory contract's kernel fields have no one-file home
today (`class`, `layer`, `reversible`, `rebuild_from`, `gates`, `invariant` /
`no_runtime_invariant`, `profile`), so they are ADDED as optional keys with PLUGIN_FORMAT.md's
meanings. Three keys neither layout has are added too: `assays` (rule 2), an exact
`wraps.version`, and `wraps.doi` (A4.3). Nothing is hand-edited, and no code moves between
repositories. The ADR names what is given up:
- the directory as the unit;
- README §15 as a checked file;
- a plugin with no Python host file;
- the per-plugin `lock.yml` (the host's group lock replaces it);
- Phase 6's "dissolve scProfile".

ADR-0004 stands, amended: the format is one, the hosts stay two, and the harness reads the format
statically. ROADMAP Phase 6 becomes "one format, read by the harness", with mounting through an
adapter left to a later wave.

**Where the catalogue reads each plugin from.** Static reads only: `ast`, the stdlib, the harness's
`yamlish`. Nothing of a tool is imported.
- **Harness:** every `plugin.yml` under the harness's shipped `plugins/` and under each
  `$SCH_PLUGINS` directory (the kernel's own search roots, minus a stack's). Id
  `harness:<profile family>/<name>`.
- **scProfile:** from `--scprofile CHECKOUT`:
  - `kernels/*.py` that is not `_*`, a one-file plugin, id `scprofile:<stem>`;
  - `kernels/*/kernel.yml`, the legacy six-file shape;
  - `kernels/<stem>.<x>` beside a plugin, its companion, never a plugin;
  - `DEVPOINTS.yaml` at the checkout root: the maker's `outstanding_if` markers (from the point
    whose `lives` is `kernels`) and `rules.end_to_end`, the only cohort-run record the tool keeps;
  - `scprofile/declare.py`'s `CAPABILITIES` literal: the tool's own vocabulary, which says which
    needs are data, design or another plugin's output;
  - `.git/HEAD`, by file: the commit read.
- **Format column:**
  - `maker`: one-file, no `outstanding_if` field set, and `<name>.signatures.json` (the maker's
    record, ADR-0026) present;
  - `one-file`: the adopted layout, not through the maker;
  - `directory` and `kernel-yml`: legacy.
- **Cohort runs:** `recorded` or `unknown`, never `no`.
- **Assays:** declared verbatim, or `not declared`, never defaulted. The static `ctx.assay`-style
  reads are listed as evidence.
- **Unreadable plugins:** a syntax error, no `PLUGIN`, a non-literal, annotated, duplicate or
  non-dict `PLUGIN`, a bad `plugin.yml`, a malformed `assays`, or an OSError are each an error
  naming the file. The command then exits 2.

**Code.** New package `sch/catalogue/` (layer 4): `read.py`, `row.py`, `command.py`. Shared
files get minimal edits:
- `sch/cli.py`: a docstring line, a 3-line `cmd_catalogue` that delegates, and the parser lines

The command is `sch catalogue [list|show] [ID] [--scprofile CHECKOUT] [--json]`. `show` accepts a
