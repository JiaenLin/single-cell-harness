## The change
- **GAP-P14 (silent data corruption).** When the sample and condition columns cross, every cell of a
  sample is relabelled to its first cell's condition. The conversion must keep each cell's condition.
  Apply the split rule Studio's exporter already uses (scrnaseq-studio `tools/export_h5ad.py`), or
  refuse by name in the CLI. Either way, the headless path checks too; today only the UI shows a
  note.
- **GAP-P10.** The run's provenance in the object's `uns` (each tool's record: the tool, its version
  and commit, the stage, the run key) is carried into the bundle as a run section, and not dropped.
  Where `uns` carries none, the bundle says so.
- **GAP-P15.** Only 2-column `obsm` entries become embeddings. Latent spaces (30-D `X_harmony`,
  `X_pca`, `X_none`) are not cut to their first two dimensions. Byte-identical duplicates are offered
  once. A note names everything that was skipped, and why.

**P14: split, not refuse.**
- **Why split.** It is the rule Studio's exporter applies (`export_h5ad.py`, the spanning split), so the
  writers of bundle@1 agree. Every cell keeps its condition with no hand work, which is A6.2's "no
  manual conversion". A sample in two conditions is real data (a hashed lane, a donor before and
  after), not a malformed object. A refusal would send the user back to rebuild the object by hand.
- **The rule.** A sample whose cells hold more than one condition becomes one sample per condition,
  named `sample|condition`. Only a split sample is renamed. Ids are ordered by the sample's level
  order, then the condition's. An id that collides with an existing one gets `#2`. With no sample
  column, the `all cells` sample is split by condition the same way.
- **Decided once, on the whole object.** The decision is made before any split into parts, in
  the CLI and in the app's worker, so a sample has one name in every part. Studio merges samples
  across parts by id. `buildBundle` applies the same rule itself, which covers every other caller.
- **Said, never silent.** A note names the split samples and the sample count before and after. The
  CLI prints it on stderr. `crossCheck`'s sentence, which the app shows, says what now happens
  instead of "the bundle will record only the first".

**P10: the run section.** Each part's `meta.json` gains `run = {searched, records}`.
- `searched` is a fixed sentence naming where the converter looked.
- `records` is a list of `{path, record}` in uns order.
- `path` is the uns path, for example `uns/scintegrate/provenance`.
- `record` is the entry converted to JSON:
  - groups become objects;
  - strings, string lists and numbers become themselves;
  - int64 becomes a number;
  - an HDF5 bool becomes true or false;
  - NaN becomes `"NaN"`;
  - anything not JSON-shaped (a dataframe, a matrix, or an array of more than 10,000 values) is named
    in place, not copied.
- **What a record is.** The rule names no tool. A record is any of these:
  1. an uns entry, or the child of a top-level uns group, named `provenance` or `*_provenance`
     (scIntegrate's `uns/scintegrate/provenance`, scAnno's `uns/<col>_provenance`);
  2. a top-level uns group whose own `schema` string names provenance (scQC's `uns/scqc`,
     `scqc/provenance@1`);
  3. `uns/harness_run`, GAP-P20's record, parsed as JSON, or kept as text with a note if it does not
     parse.
- **When nothing is found**, `records` is `[]` and a note says the object carries no run record. One
  note names the paths carried. bundle@1 readers ignore the field.
- **Not covered:** scProfile's `uns/scprofile` names provenance in neither its key nor a schema.
- The .rds reader writes no `run`. Absent means not looked.
- **Predicted on the committed fixture:** one record, `uns/scintegrate/provenance`, equal to the
  generator's dict (keys in HDF5 name order).
