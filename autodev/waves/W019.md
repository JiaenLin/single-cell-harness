# W019 (HARN): the maker's defects from the de conversion (H1-H6)

**Registered** 2026-11-09 by the coordinator, before any code or number. **Gaps** GAP-C41, GAP-C44,
GAP-C42, GAP-C39, GAP-C40, GAP-C43, all found by W013's blind conversion of `de`
(scProfile docs/MIGRATIONS.md at `0f4ff9e`). **Goals** PROF.1, A4.1, A4.2, A3.1. **Repository**
single-cell-harness (`sch dev`), base `main`, branch `autodev/W019-maker-h1-h6`.

**Why now.** The maker round's deliverable is the maker. Each held-out conversion is a measurement of
it, and the defects it finds are fixed before the next conversion (abundance). Without C41, W013's
registered "de passes the dev ladder" cannot hold, whatever de does.

## The change, in this order
1. **C41 (H3).** `agree` never compares measured resources (cores, CPU, wall time, RSS, the cost and
   memory models) between shapes. They are measurements, not outputs: they are reported, never
   judged. The baseline tier passes a fixture run that correctly refused when the fixture expects that
   refusal. File sizes are not a fingerprint of content.
2. **C44 (H6).** `jobs/dev_suite.pbs` runs every maker-layout plugin of scProfile, not
   `--name abundance` only. Baselines are recorded on the cluster (W012's job 29 shows how).
3. **C42 (H4).** `plan --migrate` never defaults an entry's axis. It derives pooled or per-unit from the
   plugin, or asks.
4. **C39 (H1).** The python extractor sees class methods and submodules: a package shaped like
   pydeseq2, with plotting methods on a class and in a submodule.
5. **C40 (H2).** The layout budget charges the host's own panels to the host, once, and not to every
   plugin. A pooled plugin gets its own budget. `host_panels` is not demanded equal to a list.
6. **C43 (H5).** `sch dev edit` wraps inserted keys like the surrounding file.

**Designs, in the registered order.** The harness gains no scProfile field name. Each new key is the
tool's own declaration.
1. **C41.**
   - (a) **Resources.** One rule lives in `sch/dev/baseline.py`, and both `agree` and the
     baseline's `compare` read it. A number is a resource of the execution when a key on its path
     names one. "Names one" means an identifier-shaped segment has a token (split at `_` and at
     camelCase) in {cores, cpu, wall, walltime, rss, memory, cost, runtime}. `time` is not on the
     list, because pseudotime and latent time are results. The rule only ever reads fixture runs, and
     a test holds every name the fixture writes outside it. `agree` compares everything else as
     before and prints how many values it compared. It lists resource fields as reported, with both
     shapes' values where they differ, and they never fail the tier. The baseline records them and
     never compares them.
   - (b) **Byte counts.** A byte count is not content. `agree` already ignores `products[*].bytes`;
     that rule moves into baseline.py, and the baseline's `compare` applies it too. An opaque file's
     identity is its content hash: its size is recorded but not compared. A missing file or an
     emptied file is still a finding.
   - (c) **Refusals.** A declared refusal is a result with no products. The fixture tier marks it
     `refused`. `agree` and `baseline` read that mark instead of a STATUS.json at a fixed path, and
     both are not applicable on a refusal. A request to record a baseline from a refusal is refused
     by name ("could not run"), and nothing is written.
2. **C44.** `sch/dev/rules.py` gains `maker_output(doc, point)`: the artefacts at a point that the
   repository's own `rules.held_out` does not hold out. With no rules block, that is every artefact.
   `jobs/dev_suite.pbs` changes as follows:
   - It writes scProfile's `kernel` names to `logs/scprofile.names.txt`, and refuses an empty list.
   - It checks each name into `checks/scprofile.<name>.txt`. The repository tiers (rules, contract,
     unit, leak) run once, with the first name; later names run only the per-artefact tiers.
   - `SCPROFILE_PREFIX`, passed with `-v`, is the site's prefix where the plugins' environments are
     built. It becomes `SCH_DEV_PREFIX` for scProfile's checks only, so the plugins run on the
     fixture. Without it they refuse, as declared.
   - `RECORD=1` records as job 29 did, for scIntegrate, scAnno and each scProfile name, into a
     recording root inside the run. That root holds the tool's DEVPOINTS.yaml, copied and
     cmp-checked; every other top-level entry, linked; and `tests/baselines` as a real directory.
     The record runs `--record-baseline` on the fixture, agree and baseline tiers, then a recheck.
     The links are removed when the job ends, and the tools' own baselines are md5-checked unchanged.
   - Base's RECORD wrote into the tool checkout (`--root ~/tools/<Tool>`), which LAYOUT forbids.
   - A new dated prediction goes in the header. I do not submit the job (rule 3).
3. **C42.** The plan stage may name the plugin field that says the plugin runs once per unit
   (`entry_keys.per_unit`). Some entries are not placed by the legacy axis map. For those,
   `plan --migrate` derives the axis: `unit` when the field is set, and `cohort` when the plugin
   leaves it empty. When the stage does not name that field, it asks: the axis is the placeholder
   with the question, counted among the worksheet's debts. It never writes `unit` from nothing.
4. **C39.** This applies where a package has no plotting submodule. The python probe also reads
   every public class the package defines, using only its own methods; inherited ones are skipped
   (pydeseq2's `DeseqDataSet` is an AnnData). It also reads every public submodule, walked with
   `pkgutil`. Private and test modules are skipped, and an import failure is named, not fatal.
   - The same three rules apply: the name, an axes or figure parameter, and a body that saves a figure.
   - Names are relative to the package: `dds.DeseqDataSet.plot_dispersions`,
     `ds.DeseqStats.plot_MA`, `utils.make_MA_plot`. Each function object gets one name, its shortest
     public path.
   - `how` says how many classes and submodules were read.
5. **C40.**
   - **`host_for`.** The layout may name the plugin field (a dotted path) that earns the host's own
     panels. When it does, a plugin without that field:
     - is charged none of the host's panels;
     - owes no host list;
     - gets no host list written by `--apply`.
   - **Plugins the host draws for.** Such a plugin is charged the list it declares, and the list may
     name any of the host's known kinds. Equality to `host_keep` is no longer demanded. An unknown
     kind is still owed. A plugin with no list still owes one, and is charged `host_keep`.
   - **`pooled`.** The layout may declare a `pooled` budget, with a budget and a keep list like an
     axis. A plugin that the plan's `per_unit` field marks as pooled is held to it instead of the
     cohort axis, which is a per-unit plugin's summary.
   - **Without the declarations.** With no `host_for`, every plugin is charged as before. With no
     `pooled`, a pooled plugin uses the cohort axis.
6. **C43.** `sch dev edit` writes an inserted key like the file around it.
   - **Placement.** In a mapping that spans lines, the key goes on its own line, indented like the
     keys that start their own lines. It goes after the first key/value pair whose line ends with a
     comma, or else before the closing brace. In a one-line mapping it goes inline, but only while
     the line still fits.
   - **Long strings.** The file's margin is the 95th percentile of its line lengths, and at least 79.
     A string value that would pass it is written as adjacent literals, split at spaces, with
     continuation lines aligned under the first quote.
   - **Where the same writer is used.** It also writes an added entry's keys, a list element added on
     its own line, and a replaced string value.
   - **Quotes and the check.** A new key takes the quote style of the key it follows. The edited
     literal must evaluate to exactly the value given, or nothing is written.
