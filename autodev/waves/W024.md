**Why now.** Rule 1's "no cohort string in a tool" is graded by one instrument, `sch conform`'s S1. Today
S1:
- never reads .ts/.tsx/.mjs/.js/.html/.sh files: it reads only TEXT_EXT, so Studio, Lab and the Service are

## The change
1. **C46.** S1 reads every tracked text file by content, not by extension; binary files are skipped by
   content sniffing. There is a test with a listed term in a .ts and a .sh file.
2. **101.** Any named list that is missing, or that yields 0 terms, is an error, whether one list or several
   are named.
3. **008.** `sch conform terms build <cohort>` GENERATES a cohort's list from its records: the design
   sheet's factor levels and sample names, and the counts and percentages in its RUNLOGs, DECISIONS and
   PROMOTED files (comma-grouped, plain 2-6 digit counts beside a measurement word, "N of M", margins),
   plus a hand-kept stems file. It writes to scratch and never edits a cohort's docs.
   - **Per-tool scoping:** a declared allow-list per repository, for content a tool legitimately holds,
     such as scAnno's reference trees naming a cell type. Each entry carries its reason.
   - **False positives:** the builder runs the generated SAMBO and C46 lists over all eight repositories
     and reports every hit, each classed as leak or false positive.
4. **110.** The harness's record paths (GOALS.md, autodev/, docs/adr/, docs/blind/, docs/postmortem/) are
   exempt from S1 by declaration. The pre-commit hook reads the cohort lists from an untracked local file
   when present.
5. **C38 (ladder).** The dev ladder reads `STATUS*.json` (scAnno writes `STATUS.<cmd>.json`).

### 1. The generator's extraction rules (`sch conform terms build COHORT --out FILE`)
Reads, never writes, the cohort: `stages/*/design*.csv`, `stages/*/samplesheet*.{tsv,csv}` (`#`
lines skipped), `stages/*/{RUNLOG,DECISIONS,PROTOCOL}.md`, `stages/*/PROMOTED*.md`,
`results/*/PROMOTED*.md`, and `docs/forbidden_terms.txt`. `--out` is required, and a path inside
the cohort is refused. Every term is written under a comment naming its source `file:line` and the
line's text.
- **carried:** every line of the cohort's `docs/forbidden_terms.txt`, verbatim and first (so the
  result is a superset of today's list, prediction 1).
- **sample:** every value of the sample column of every sheet.
- **level:** every value of every other column that is a factor: at least 2 distinct values, fewer
  than the rows (for a samplesheet), not numeric, not a path, and **not one of the profile's
  `axes`** (species, assay, platform, chemistry, mt_prefix, ...: the field's vocabulary, named by
  every tool that supports it; a literal default of one is S13's finding, not S1's). A level of one
  character is dropped and the drop is written into the list (it cannot be told from text).
- **count:** comma-grouped numbers (`3,799`) that are not round (value mod 100 != 0: a round
  number reads as a setting); the plain form too from 10,000 up (a 4-digit plain number is a year
  or a port). Not inside a longer number or a dotted version.
- **measured:** a 2-6 digit count beside a measurement word, as the phrase (`47 nuclei`,
  `held 455`): nouns (cells, nuclei, genes, barcodes, droplets, reads, UMIs, features, clusters,
  samples, libraries, animals, mice, markers, doublets, labels, organoids, donors) after the number,
  and a few verbs (held, kept, removed, dropped, retained, withheld, flagged, predicted) before it.
- **fraction:** `N of M` with M >= 10 (`130 of 190`, `4 of 10`); smaller M are left out as
  ordinary prose.
- **percentage:** a percentage with a decimal part (`29.2%`), except one-decimal values ending in 0
  or 5 (settings).
- **margin:** a decimal of 2+ places beside a margin word (`gap 0.64`, `AUC 0.6147`, `ARI 0.93`),
  and any decimal with 4+ significant digits (`206.88`, `0.6147`).
- **stems:** a hand-kept file (`--stems FILE`; default `docs/leak_stems.txt` when present), its
  lines verbatim. For SAMBO this wave writes one into scratch from the handed-back first-study words
  (W012's cardiomyo/matrifibro/endocardial; scProfile's guard :81-82, B1-095).
- **carry:** `--carry FILE` (repeatable): handed-back lists (W011's two), each term with its
  `file:line` there and, when found, its first line in the cohort's text; a line that is a
  description rather than a term (`"/10" as a literal`, `this cohort's size`) or a regex
  (`109,?140`) is written as a comment saying why it is not a term.

### 2. How a term is matched, and the scoping format
- **The list's syntax grows two prefixes**, so that the children's own guards, which read every line
  as a case-insensitive substring, see a generated line as a literal that never occurs (installing
  the list cannot turn a child's suite red): `word:T` matches T as a whole token in any case (not
  inside a longer run of letters and digits, and a number not inside a longer number: `3,799` does
  not match `13,799`); `exact:T` the same in T's own case; a trailing `*` makes either a prefix
  (`word:cardiomyo*`). A line with no prefix keeps today's meaning. Spaces in a term match any run
  of whitespace. Generated levels of 2-3 characters are `exact:` (measured: `wt` variables, gzip's
  `"wt"` mode and the CSS property `--mut` are what those letters are in other cases); everything
  else generated is `word:`.
- **A repository's scope** is `LEAK_SCOPE.txt` at its root, one entry per line,
  `<path> :: <what may appear> :: <why>`, `#` comments. `<path>` is repository-relative; a
  trailing `/` takes the directory, globs as fnmatch. `<what may appear>` is `*` (a record: S1 does
  not read it, and S1f says how many files that covers) or a comma list of listed terms (and shape
  names) that may appear there; nothing else at that path is excused, and those terms are still
  found everywhere else. `<why>` is required: an entry without one, or that does not parse, fails
  S1f and is not applied; an entry that matches no file is a warning (S1g). Scoped findings are kept
  in S1f's evidence, so they stay visible. The file may name the terms it allows; anything else in
  it is still found. Living in the repository, every entry is reviewed in that repository's
  history; no cohort string has to be written into a tool, because an entry is needed only for a
  word the tool legitimately holds already.
- The harness's `LEAK_SCOPE.txt`: the five registered record paths, plus the emitted job records
  above (one entry each, the reason "the script of one submitted run, cited by its ADR").
- Proposed entries for the eight repositories go to scratch, one file per repository, and are
  validated by re-running S1 on scratch copies with the entries in place; no tool is edited.

### 3. Binary sniffing and the file set
S1 (and the dev ladder's leak tier, which asks the same question) reads every file git lists
(`ls-files --cached --others --exclude-standard`: tracked, plus new files not yet ignored), or the
whole tree outside SKIP_DIRS where there is no git (a compute node). A file is binary when its first
8 KiB hold a NUL byte or are not UTF-8 (allowing a character cut at the boundary); binary files are
skipped and counted, symlinks are not followed. The other rules (S2-S5) keep their extension-based
listing: this wave changes what S1 reads, not what S4 calls a job script.

### 4. GAP-101, the record-path exemption, C38

  (exit 2, the file named), never a traceback. The ladder's contract tier stops dropping a
  `A:B` terms argument (`Path(spec).is_file()` was False for two lists), and its leak tier reports
  a refused list as a failed tier.
- The pre-commit hook reads `setup/githooks/conform.local` (untracked, ignored; `terms=` and

- C38: the fixture tier and `agree` read `STATUS.json` and every `STATUS.<cmd>.json`; a command
  whose per-command status is not `ok` fails the tier as `STATUS.json` would, and an accepted
  refusal is read from either.
