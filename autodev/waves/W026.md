## The change
- **An `anno@scanno` adapter**, in the Universal Plugin Format of ADR-0030 and following W010's
  `qc@scqc` pattern. It calls scAnno's REAL CLI through the kernel, with the commands and order of
  SAMBO's stage-2 chain (cluster, annotate per sample, scope, annotate --scope, rescue) as job 25
  runs them. It takes stage 1's deliverable as its observation, read-only and pinned (E2).
- **Labels are layers, not removals.** The adapter adds scAnno's label columns as a reversible layer.
  It never edits the observation. Unmounting restores the pre-mount digest, as for `qc@scqc`.
- **No assay default (rule 2).** The adapter passes the assay declared for the run. scAnno refuses a
  mixed or unknown assay itself (W011).

### 1. The adapter: labels become a reversible layer
- **Format.** `plugins/single-cell/anno@scanno/`, a `plugin.yml` directory. ADR-0030 point 5
  requires that form for any plugin the kernel itself mounts, because the kernel cannot mount the UPF
  yet. It carries the UPF keys a directory can carry: `assays: [scrna, snrna]` and an exact
  `wraps.version` (0.12.0). scAnno declares no DOI, so none is invented.
- **Manifest fields.** `class: method`, `layer: stack`, `reversible: true`, `state_version: 1`.
  - That `state_version` must equal scAnno's: `scanno describe` is checked before any compute, as
    `qc@scqc` does.
  - `needs: [observations/raw]`; `provides: column/*, table/*, object/*`.
  - No mask and no gate. The profile requires `differential_check` only on masks.
- **Each part's labels.** The chain's last object for a part is its delivered object: rescued if
  `rescue` ran, otherwise annotated. The layer is **exactly what scAnno changed**, read from that
  object's obs and compared with the part's own obs, by identity (`<sample>|<barcode>`):
  - every column the part lacks (added);
  - every column the part carries that scAnno rewrote with different values (rewritten);
  - never a column the part carries with identical values. That column is the observation's own,
    unchanged, so it is not attributed to scAnno.
- **What the layer contributes.** Each column is one whole contribution of the final values, over
  every observation.
  - The observations are never written. Unmounting removes exactly those columns, so the view's
    digest returns to its pre-mount value (E4 tests this at mount; A1 re-checks the pin after
    every run).
  - The adapter records any column scAnno dropped. It is never removed from the view, because the
    view never held it.
- **Reading obs.** Obs is read with h5py. The kernel already needs h5py for parts, and anndata
  is not needed. The reader decodes the anndata dataframe encodings: numeric and bool datasets,
  string-array, categorical (code -1 is missing), and nullable integer, boolean and string.
  - Any other encoding is an error that names the column. It is never skipped.
  - The fake-scAnno tests and the real-scAnno run both exercise it.
- **The stage record is scAnno's own, adopted.**
  - After each call the adapter reads `STATUS.<cmd>.json` and its seal beside the output.
  - `ok`, `SEALED.<cmd>.txt` and exit 0 mean the chain goes on.
  - `refused` (exit 2) refuses the mount with scAnno's reason and fix.
  - Anything else is a death that quotes the headline.
  - The ten `annotate` calls share one directory. Each `STATUS.annotate.json` is therefore copied,
    as the call ends, to `status/annotate_<sample>.STATUS.json`, the copy job 25 makes.
  - `answer` carries each command's record, its argv and the layer's column lists.
    `wrapped_versions` carries scAnno's version and commit.
- **Companion.** It checks two things:
  - the layer contributes no mask: labelling removes nothing;
  - every layer column covers every observation the stack holds: scAnno's chain lost none.
- **Rule 2.** The adapter refuses before any scAnno process when the stack declares no `assay`
  (`profile_context`).
  - It passes the declared value verbatim as `annotate --assay`. A parameter cannot set it.
  - It does not check the value. scAnno refuses an unknown assay, and a mixed one in
    `rescue`/`scope` (W011).
  - `cluster` and `rescue` take no assay.

### 2. The observation, pinned
- **The manifest.** `sch init --observations <manifest> --parts h5ad --key sample=sample --context
  assay=<declared>`. The manifest has one row per library: `sample` (the profile's `{sample}`) and
  the library's object.
- **What init does** (W010's machinery, unchanged): it reads every part's barcodes through h5py,
  pins the digest and each file's fingerprint, and refuses a writable manifest or part.
- **How the adapter treats the parts.** It hands them to scAnno in place, as `--h5ad`, and never
  writes them. scAnno writes only under the run's `out_dir`.
- **The adapter refuses:**
  - a view with anything masked beneath it. scAnno reads the parts themselves and would label
    observations the stack had set aside;
  - two parts with one file stem, because `cluster` names its outputs `<stem>_clustered.h5ad` and
    one would overwrite the other;
  - a sample name that cannot be a file name.

### 3. scAnno's commands, in order (the real CLI, `[python, <scanno>, cmd, ...]`)
- **The parameters.**
  - `scanno` (the CLI's path, verbatim) is required, with no default.
  - `cluster`, `annotate` and `rescue` are JSON objects of each command's own flags, by scAnno's names
    (`-` written `_`). `annotate` is required; the other two run only when declared.
  - The flags are emitted in scAnno's parser order (d0ee926). A list on an `append` flag
    (`cluster_key`) repeats it. True is a bare flag; false or null is absent, and an absent flag
    keeps scAnno's default.
  - An unknown flag, an unknown top-level parameter, or a flag the adapter owns is refused, naming
    it.
- **The commands, in order:**
  1. `describe`: `state_version` must be 1.
  2. `cluster --h5ad <every part, manifest order> --out-dir <P>/clustered <declared>`
  3. per part, in manifest order: `annotate --h5ad <P>/clustered/<stem>_clustered.h5ad` (the part
     itself when `cluster` is not declared) `<declared> --assay <declared> --out-h5ad
     <P>/annotated/<sample>.ladder.h5ad`
  4. `rescue --h5ad <the annotated objects, manifest order> <declared> --out-dir <P>/rescued --out
     <P>/rescue/rescue.json --out-table <P>/rescue/impact.csv --out-report <P>/rescue/rescue.html`
- `P = out_dir/scanno`. Below `P` the layout is job 25's, file for file, so job 25's comparison reads
  it unchanged. Logs go to `P/logs/`.

### 4. The paths the kernel owns
These are everything under the plugin's `out_dir`, i.e. `<stack>/plugins/anno_scanno/out/scanno/`
(job 25: `$RUNDIR`):
- cluster `--out-dir`;
- annotate's `--h5ad` (cluster's outputs) and `--out-h5ad`;
- rescue's `--h5ad` (annotate's outputs), `--out-dir`, `--out`, `--out-table` and `--out-report`.

Every other argument is the declaration's: the parts, the four references, every flag value and
scAnno's path. The job's argv check substitutes the run directory for P in 782921's own recorded
argv (`STATUS.<cmd>.json` of every call). It then compares the calls as argparse reads them: each
flag with its values, and a repeated flag's values in order. The order of distinct flags is printed
and not graded, since argparse reads none and the adapter writes scAnno's parser order.

### Fix-up D1 (builder, 2026-11-09, commit `f640455`; a dated correction)
At `88ba42d` two sentences were false: section 1's "A parameter cannot set it" and the README's "A
parameter naming any of these is refused". The verifier's D1 showed why.
- run.py wrote any value other than true, false or null as `--flag <value>`. annotate's
  zero-argument flags take nothing, so scanno's parser read that value as an option.
- Through the real scAnno, `resolve: "--report=…"` wrote beside the libraries (E2), and
  `background_from_clusters: "--assay=snrna"` overrode the stack's scrna (rule 2).

From `f640455` these are refused by name, before any scAnno process:
- any value other than true, false or null on a zero-argument flag. These are `BARE`, taken from
  d0ee926's parser: annotate's `resolve`, `background_from_clusters`, `no_exclude` and `use_raw`;
  cluster and rescue have none;
- true on a flag that takes a value;
- any value beginning with `-`, including every list element, scAnno's path and the stack's assay.

With that, both sentences are true.
