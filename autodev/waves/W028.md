## The change
- **GAP-P19, a Run card.** Studio shows the run that produced an object, from the bundle's `meta.run`, as Lab's W017
  writes it (`{searched, records[{path, record}], leftOut, notes}`; Lab branch `autodev/W017-lab-integrity` @
  `d5b0244`):
  - each record's tool, version or commit, stage and run key, as recorded, never inferred;
  - records named but not copied (over budget) are shown as named, with their size;
  - with no `run`, the card says the object carries no run record.
- **GAP-C52, Studio's part.** Studio's pseudobulk header parser (bundle.ts:332, collection-source.ts:710) splits on
  `||`. Since W017, a split sample id can hold `|` (`sample|condition`, `#2`), so a level that is empty or holds `|`
  orphans that sample's pseudobulk columns. Parse so that no id W017 can write is misread (for example from the right,
  or by the bundle's own declared delimiter), with a cross-repository test on W017's outputs.

**C52, the header.** Lab and both of Studio's exporters write `sample||cluster||nCells`, with the ids unescaped.
- **The count is read from the right.** The last `||` must be followed by digits only, and a count holds no `|`.
- **The boundary is read against the bundle's own declared levels.** The sample/cluster boundary is the one `||`
  whose left side is an id in the part's `meta.samples` and whose right side is a level in its `meta.clusters`.
  Every id W017 writes is declared there (the same `sample.levels`), so the true reading is always a candidate.
  On the probe, `s2||x||TypeA||2` has two `||` before its count, and only `s2||x` | `TypeA` is declared.
- **Two declared readings: refused, not guessed.** The pseudobulk table is not offered, and a note names the
  header. This needs, for example, samples `a` and `a|` together with clusters `|b` and `b`. `hasRawCounts` then
  reads false, as the collection path already reads it when its table does not survive.
- **No declared reading** (a malformed or foreign table): the old `split('||')`. So a header with no `|` in its
  ids parses exactly as before.
- **One parser** (`readPseudobulkHeader`, exported from `bundle.ts`), used by `parsePseudobulk` and by
  `mergePseudobulk`, each part against its own declared levels.
- **The merge key** becomes `JSON.stringify([sample, cluster])`. Today `a`+`|b` and `a|`+`b` share `a|||b`, and
  two columns would be summed into one.
- **Same defect, Studio's own scripts.** `scripts/make-collection.mjs` assigns columns to parts by
  `h.split('||')[0]`, and `check-real-collection.mjs` keys columns by the joined string. Both move to the parser
  and the key above. The exporters' header format is unchanged.
