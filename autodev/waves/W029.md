## The change
1. **C63 (sch/dev).** A declared `fixture.execution_record` glob may match JSON leaves only. A match on a CSV column is a
   declaration error that fails `agree` and the baseline. The key part of each glob must begin with a literal segment.
   There are tests for `["*"]`, `*.csv::*` and a result column.
2. **C57 (kernel).** The pin is re-resolved. `changed()` also reports when the resolved file set differs from the pin's
   (a re-pointed `latest -> v2` symlink), naming the file.
3. **C58 (dataset).** A missing pin is never silently re-created when events.jsonl records `observations/pinned`.
4. **C59 (executor).** qsub has a timeout, and a reconcile step (qstat by job name) runs before any resubmission, so a
   timed-out qsub that did queue the job is never doubled.
5. **C60 (docs and pin).** A hard link's ctime change is documented as a refusal reason with its remedy. The chmod
   remedy for a part made writable after init says that a new init is needed. The docs' overstatements are corrected:
   "nothing re-baselines", "each file's digest", and "re-checked before anything is read". The pin is checked before
   `Stack()` reads parts.

### The changes, in this order
1. **C63 (`sch/dev/baseline.py`, `ladder.py`).** One parser for `fixture.execution_record`, read by `agree`, the
   baseline's check and its record.
   - A glob is `product::key`, with exactly one `::`. The two parts are matched separately, so no `*` crosses `::`.
   - In the product, `*` stays inside one path segment and never crosses `/`. In the key, `*` may cross `.` and
     `[i]`, because de's 14 globs need it (`cost_model.*` matches `cost_model.de.points`).
   - The key's first segment, the text before its first `.` or `[`, must be literal and non-empty. So `*`,
     `*.csv::*`, `x::*` and `x::cores*` are declaration errors.
   - A glob that matches a CSV or TSV column is a declaration error. The column is never excused.
   - Each declaration error fails `agree`, `baseline` check and `--record-baseline`, naming the glob and the field.
   - JSON leaves are excused exactly as before.
2. **C57 (`sch/services/dataset.py`).** `changed()` also compares the files the declared path resolves to NOW with
   the pin's files. A file now read but not pinned is named, and so is a pinned file no longer read. The manifest
   is parsed only once its own path and fingerprint check out.
3. **C58.** A missing pin is refused when `events.jsonl` records `observations/pinned`. This holds after every
   plugin run, in `changed()`, so the A1 check after the deleting plugin fails at once, and on every later read.
   - A pin whose digest is not the one `events.jsonl` recorded is refused. That is the same harm by a rewrite
     instead of a deletion, and the event already carries the digest.
   - Only a stack with no pin and no such event (made before pins existed) is pinned on its first read. That pin is
     recorded as an event.
   - `fork` records the pin it copies.
4. **C59 (`sch/services/executor.py`).** `qsub` runs under `pbs.qsub_timeout_s` (default 120).
   - Every job script carries a per-submission token, `#PBS -v SCH_SUBMISSION=<token>`. The job name is unchanged.
   - When a qsub timed out, or exited 0 without an id, it may have queued the job. Before any resubmission, a
     reconcile asks qstat by job name: `qstat -x -w -u <user>` gives the rows with our name, and `qstat -x -f <id>`
     confirms each by its token.
   - Found: that job is adopted, with no second qsub. Positively absent: one resubmission, bounded by
     `pbs.qsub_retries` (default 2). Unknown (qstat failing or empty, no user): nothing is resubmitted. The mount
     is refused, naming the job name and the token. The submission stays on the executor, and quiesce qdels it once
     found, or fails E5. The refusal never leaves an unwatched job silently.
   - A qsub refused with an exit status (a full queue) created no job, so its retry is unchanged.
5. **C60 (docs and pin).**
   - The pin is checked before the first read of the observations. `ids`, `inventory`, `writable` and `digest` all
     check it first, so `Stack()`'s restore of contributions and `plan()`'s inventory no longer read a part before
     the check. A part corrupted in place then gets the A1 error naming it, not an h5py traceback.
   - When only `ctime` moved, the refusal says so: a chmod, a chown or a new hard link moves it without a byte
     changing, and the remedy is a new `init` over the same files. The docs carry the same reason and remedy.
   - The `chmod a-w` remedy for a writable part says that a new `init` is needed afterwards.
   - Corrected: "nothing re-baselines a stack", which now states the two re-pins (init, and a first-read pin
     recorded as an event); "each file's digest", which is one digest over all files plus each file's stat
     fingerprint; and "re-checked before anything is read", now true and said precisely.
6. **The coordinator's item (`_h5ad_structure`).** An obs/var index written as a group is read by its encoding:
   `nullable-*` from `values`, `categorical` from `codes`. A dataset is read by its shape, as before.
