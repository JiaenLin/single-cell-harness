  the term generator's lane as a finding and is not edited away.

  (the held-out rule; B1-065 read to the PI's words). Record them as still open.

**The change (scProfile).**
1. `scprofile prose <plugin> --replace OLD NEW [--replace ...] --why WHY [--dry] [--as-version V]`, the maker's verb
   for prose. OLD must occur exactly once. The admission: the file's CODE is unchanged. Code here means the syntax tree
   with docstrings set aside, and each embedded R script with its R comments set aside. An R script is detected by the
   suite's own rule: a module-level string of 200 or more characters holding `library(` and `<-` or `function(`. Its
   comments are found by a lexer that knows R strings, backticks and raw strings. Comments inside the declaration count
   as prose: the literal's value is compared. Refused: any other string, a splice marker (`__NAME__`), an encoding line
   or shebang, a file that does not parse, and an edit with no `--why`.
2. Recorded like any other maker edit. The entry goes into the plugin's maker record (`kernels/<plugin>.design.json`,
   the record of every answer outside the declaration) with `kind: prose`, its diff, both digests, the reason, the
   version and the declaration it left. The maker's minor version bump applies. `design_record_check` and
   `--replay-into` admit a prose entry again by the prose rule. A record needs an anchor, so DEVPOINTS gains
   `rules.end_to_end.anchor.cellchat` at `6f970e5`. Any plugin without an anchor, which is every held-out one, is
   refused by the verb. The held-out rule is then enforced by the verb itself.
3. Its followers are the tool's declared `plan.after_edit`, read from DEVPOINTS and run in order with the verb's own
   interpreter, stopping at the first that fails. It is the same list `sch dev edit` runs. **So the harness's followers
   need no change**: `sch dev edit` stays the declaration's verb (ADR-0026), and the new verb reads the declared list
   itself. The only harness file is the gate's dated job copy, on the harness branch from `autodev/train-harness-1`.
