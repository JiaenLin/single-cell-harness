## What "top level" means here (the rubric the builder designs to and the verifier looks for)
1. **Layout.** One stable shell. The plot owns the space; controls are grouped by task in one place, details in another.
   Nothing jumps when data arrives. It holds from 1280 to 2560 px wide and folds to one column when narrow.
2. **Hierarchy and type.** One type scale (four or five sizes), at most two families, tabular numerals for numbers,
   sentence-case labels, one weight for emphasis.
3. **Colour.** Tokens for surface, text, border and accent; light and dark themes; text contrast at WCAG AA. Categorical
   palettes safe for colour-blind readers (checked, not assumed); expression on a perceptually uniform scale; colour never
   the only cue.
4. **Spacing and density.** One spacing scale (4 px steps), aligned edges, one control height per size.
5. **States.** Empty, loading, error (saying what to do), no data and large data are designed for every panel.
6. **Interaction.** Everything reachable by keyboard with a visible focus; fast search for genes and cell groups;
   tooltips give exact values; a selection can be undone.
7. **Charts.** Axes labelled with units, legends that name what is plotted, n shown, a figure exported at publication
   quality.
8. **Motion.** Short (200 ms or less), purposeful, interruptible, off under reduced-motion.
9. **Speed.** The scatter stays responsive at the fixture's largest size; measured before and after, no regression.
10. **Truth.** Every number is shown as recorded and the Run card's fields are never inferred (W008, W028). The design
    changes how things look and where they sit, never what the data says.

## The change, in runs of about 150 calls
- **Run A (this registration's first builder):** run Studio on the synthetic fixture; screenshot every screen as it is
  (3 widths, the themes it has); audit it against the rubric; choose the layout model among at least three considered,
  with the reason; write `docs/DESIGN.md` (tokens, layout model, component rules); build the tokens, the shell and the
  main explorer screen.
- **Run B:** the remaining screens and panels, the states, the charts.
- **Run C:** motion, the export, the before-and-after gallery, the last polish found by looking.
Each run hands back; the next is launched from what it returns.

## Acceptance check
- Before and after screenshots of every screen (3 widths, light and dark), from the synthetic fixture only, never from a
  cohort's data.
- Every existing check passes (1,699 at W028's head); a snapshot changes only where the design changed, each one listed.
- A contrast and keyboard pass (an automated accessibility check plus a tab-through); the speed measurement.
- No change to what any number, label or Run-card field says: shown by the data-level checks passing unchanged.
- A verifier who judges by looking, against the rubric, on the built branch.
