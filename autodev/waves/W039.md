# W039 (INT): withheld cells out of the PCA

**Registered** 2026-11-11 by the coordinator, before any code or number. ROUTE item R20, the wrong-result part (GAP-128,
with GAP-C65). **Goals** INT.1, A2.1. **Repository** github.com/JiaenLin/scIntegrate, branch
`autodev/W039-withheld-pca`, from `main` (`b148030`, W012 + W025 merged 2026-11-11).

**Why first in this repository.** The audit (pass 0004) found that withheld cells stay in the PCA every method is fitted
on whenever the input carries `X_pca` (the PCA is not refit after withholding), and that the deliverable keeps their
`X_pca`, while docs/METHODS.md says they are not in the PCA. That is a wrong result in a promoted output. The PI is to be
asked once whether to re-promote stage 3 (harmony is deterministic since W025 and its rank moved); the question waits for
this fix so that one re-promotion carries both.

## The change
1. **GAP-128.** Refit the PCA on the retained cells, or take the input's PCA only when the run declares it and the record
   says so. A test that fails on `b148030`. docs/METHODS.md made true.
2. **GAP-C65.** harmony crashes on a batch column holding an unused category (`operands could not be broadcast (67,6)
   (67,7)`), and STATUS.json still says ok. Drop unused categories before the fit; STATUS says `partial` and names the
   method when a requested method fails. A test that fails on `b148030`.
3. **A reproduction job** in the first cohort's `stages/03_integrate/jobs/` (the model: `30b_w012_w025_reproduce.pbs`),
   prediction in its header before any run, submit recipe between `# SUBMIT-BEGIN` and `# SUBMIT-END`, a final `GATE:`
   line. The prediction names, per method and per output, what must stay identical to the promoted run and what the PCA
   refit must move, with the direction or bound where the builder can derive one. The cohort has 2,086 withheld cells of
   100,713.
