## The change
1. Every hit outside `kernels/`: the site string goes. Where a line cites a job as evidence, it cites what the run
   established, or the run's record by a name that is not a site string; it does not lose the fact. Where code or a job
   template hard-codes a queue or a site value, the value comes from the declaration or the site's own configuration,
   as scQC's resources do since W020 (B1-043), with a test that fails on the base.
2. Hits in `kernels/` of plugins that are NOT held out (cellchat is done; `de` is spent): through the maker's prose verb
   (`scprofile prose`, W035), recorded like any maker edit.
3. Hits in the seven held-out plugins are NOT touched: list them, by file and line, as what their own waves must remove.
4. No excuse is added to LEAK_SCOPE to make a hit pass.
