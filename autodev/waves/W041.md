# W041 (HARN): one request, every stage (the driver, run 1)

**Registered** 2026-11-11 by the coordinator, before any code or number. ROUTE item R03, first run. **Gaps** GAP-001
(the driver part), GAP-C49 (step 2's declaration). **Goals** A1.1, A1.2, HARN.1. **Repository**
github.com/JiaenLin/single-cell-harness, branch `autodev/W041-driver`, stacked on `autodev/W036-prof-adapter` @ `dcbc0df`
(all four adapters: `qc@scqc`, `anno@scanno`, `int@scintegrate`, `prof@scprofile`).

**Why.** A1.1's words: "From one cohort's processed matrices and a design sheet, the family runs QC, annotation,
integration and profiling, writes every stage's report, and seals the run. No glue script is written for the cohort, and
nobody steps in by hand between stages except for decisions the tools declare as the user's." Today each stage goes
through the harness by its own hand-written job of 500 to 1,000 lines per cohort. Those jobs are reproduction tests, and
they stay. What is missing is the ordinary path: one request in, four mounts in order, the user's decisions asked by
name, a sealed run out. R04 (the Service request), R07 (the cohort-run skill), R08 (the UI) and R15's later stages all
stand on it.

## The change (run 1: the request, the plan, the local path)
1. **One request file, as data:** where the matrices are, the design sheet, the context every adapter already requires
   (assay, species or organism, tissue), and per stage only what a tool declares as the user's to choose. No cohort or
   site string enters the harness; the request lives with the cohort.
2. **The plan from the request:** the four mounts in order, each stage reading the stage before it from the stack (not
   from a promoted path), with every user-owned decision named before anything runs, and what a tool cannot run under
   this design said by that tool, not by the driver. Use the kernel's existing verbs and records (`plan`, `mount`, `ask`,
   `report`, `events`) and add the smallest thing that chains them; read the ADRs before adding a verb.
3. **The words settled once:** one spelling per assay across the four adapters (stage 2's stack still writes `sn`, a
   third spelling), and `species` and `organism` declared once for one fact. The adapters keep translating into each
   tool's own words; the request does not carry three spellings.
4. **Step 2 of the ten typical steps, ambient removal:** declared upstream by name in the request and the record (which
   tool produced the input matrices, and whether ambient removal ran), as alignment already is. Single cells are never
   sent to a nucleus-calibrated remover (rule 2, the PI's rule of 2026-10-02).
5. **The local path, end to end, on the synthetic two-shape fixture:** one command with one request runs the four stages
   through their adapters (stand-ins in the suite; the real tools where the workstation has them), stops at a user-owned
   decision with its name and resumes from the answer, writes each stage's report and seals. A failed stage leaves a
   record that says which stage, why, and how to resume.

Run 2 (a follow-up registration): the cluster path (the kernel's pbs executor, a job generated from the request, never
hand-written) and the first cohort's chained run, stage 1 to stage 4, with its prediction.

### Builder's plan (builder, 2026-11-11, before any code; clone at `dcbc0df`, branch `autodev/W041-driver`)

**What exists (read first).** `sch run --stack D` already chains mounts: `Stack.run_declared()` mounts every plugin
`stack.yml` lists, in order (kernel.py:716). `sch plan PLUGIN` is the kernel's per-mount plan (admitted, needs, missing,
gates, cannot_show). Every stage's adapter reads ITS OWN stack's observations as a parts manifest, read in place and pinned
read-only, and refuses a masked view beneath it, so a cohort's four stages are four stacks, not four mounts on one: stage 2
reads libraries after QC, stage 3 ONE joint object, stage 4 the integrated object. What no code says: which object of a
stage is the next stage's observations (each adapter's `object/*` is unlabelled), and which choices are the user's (scQC
declares them as `escapes`, scProfile in prose, the kernel only as gate escapes). The stage-2 -> 3 join is scAnno's own
`embed` (W034 §0: SAMBO's stage 3 reads `results/02_annotate/joint/...`, written by `scanno embed`), which no adapter runs.

**The smallest addition** (no new verb; two existing verbs extended, one kernel-side module):
1. **The request** (`request.yml`, read by the harness's own yamlish; lives with the cohort): `observations` (the samplesheet,
   a parts manifest), `parts`, `keys`, `design`, `context` (profile axes: `assay`, `species`, `tissue`, ...), `upstream`
   (`alignment` and `ambient`, each `{tool: <name>|none, ...}`), and `stages` in order, each `{plugin, params}`. The schema
   is in `sch/drive.py`; a synthetic example is `docs/request.example.yml`. Nothing cohort- or site-specific in either.
2. **Declarations, in each adapter's plugin.yml** (read by the plan, never by the kernel's mount): `reads:` the shape of
   observations it reads (`libraries` | `joint`), `hands_on:` the shapes it hands the next stage, and `decisions:` the
   choices its tool declares as the user's, each `{name, param, what}`: qc@scqc `mode` and `decisions` (scQC's own
   `escapes`: the apply step, a derived threshold); prof@scprofile `control` (the sign convention, tier II). anno and int
   declare none (their tools declare none). Each adapter's out.json answer gains `hands_on` (the paths of what it hands on,
   relative to its run): qc the per-library objects (`objects/cohort_per_sample/<s>.filtered.h5ad`, scQC's layout) and the
   joint deliverable; anno its final per-library objects and, when the stage declares scAnno's `embed`, the joint object;
   int and prof their object. anno@scanno gains scAnno's `embed` as one more optional command in its own pattern
   (FLAGS/OWNED/BARE from scAnno's parser), off unless declared, so job 28's declaration runs the same calls.
3. **`sch plan --request R`**: the four stages in order, each with its plugin's resolution, reads/hands_on matched against the
   stage before it, the given params ("every other flag: the tool's own default"), the user's decisions by name, and
   cannot_show. Nothing runs, nothing is written. **`sch run --request R --out D [--answer NAME=VALUE ... --by WHO]`**: per
   stage, `Stack.init` (observations = a manifest naming the previous stage's handed-on objects read from that stage's stack
   record, never a promoted path), the stage's plugin declared in its `stack.yml`, `run_declared()`, `report()`, then the
   stage sealed (its out/ read-only, `SEALED.json`). A declared decision unanswered stops the run BEFORE that stage (exit 3,
   `D/DRIVE.json` status `waiting`, the decision's name and what it is, the resume command); `--answer` records it
   (`D/decisions.json` and a `decision/answered` event in the stage's stack) and the same command resumes; a sealed stage is
   never re-run. A request that sets a declared decision as a plain param is refused (the driver never answers one). A
   failed stage: exit 2, DRIVE.json `failed` naming the stage, the adapter's reason and fix, and the resume command; the
   failed stage directory is kept (renamed) as its record.
4. **Words settled once (point 3):** the request's assay must be a word every stage's adapter declares in `assays:` (all four:
   `scrna`, `snrna`; qc@scqc gains the line it lacks), so `sn`, `cell`, `nucleus` are refused before any tool, naming the
   family's words; each adapter keeps its translation (prof: `cell`/`nucleus`). One fact, one axis: the request declares
   `species` and is refused if it declares `organism`; prof@scprofile translates a declared `species` into scProfile's
   organism word (`mus_musculus` -> `mouse`, `homo_sapiens` -> `human`, its `detect_organism` words) when no `organism` is
   declared, refuses the two disagreeing, and leaves any other species undeclared to scProfile, said as today.
5. **Step 2 (point 4):** `upstream.ambient` is required, by name (`tool: none` is a declaration). The profile declares the
   rule once (`upstream: {steps: [alignment, ambient], never: {scrna: {ambient: [cellbender]}}}`, rule 2), so a single-cell
   request naming CellBender upstream is refused before any tool; every stage's stack records `upstream/declared`.

**Tests** (`tests/test_one_request_every_stage.py`, stand-ins, both fixture shapes' role names): the refusals before any tool
(no assay, `sn`, `organism`, scrna + CellBender, a decision set as a param); the plan; the stop at `qc.mode`/`qc.decisions`
