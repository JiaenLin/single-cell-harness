## The change
1. **The cluster path.** `sch run --request` with each stage's stack on the kernel's pbs executor, the site's facts from
   the site file (rule 1: no queue, no path and no cohort string in the harness). Per-stage resources have no home yet:
   decide where they are declared (a tool's declaration for defaults, the request for a cohort's sizes, the site file for
   queues) and say why. A job for a cohort is GENERATED from its request (one `sch run --request` with the recorded
   answers), never hand-written.
2. **GAP-C91, what each stage cost.** When the executor reconciles a task with the scheduler it records that task's wall
   time and peak memory as the scheduler reports them, and the stage's report gives the stage's cells, wall time and peak
   memory (A3.4's words). A test with the stand-in scheduler.
3. **GAP-C92, one library key.** scQC writes the library column as `sample` whatever the cohort calls it, and scProfile
   joins the design sheet on `--sample-key`, so run 1's second fixture shape dies at stage 4 (stand-in: `KeyError:
   'sample'`). First measure what the real scProfile does. Then make the request's `keys.sample` one declared fact that
   every stage honours, with the fixture's second shape running to the seal.
4. **The first cohort's request and chained run.** The request file as data in the cohort's folder, every value looked up
   in the cohort's records, none invented: the design sheet and its library column, upstream alignment and ambient
   removal by name, scQC's recorded decisions, the DE control. The generated job runs stage 1 to stage 4 from that one
   request. Its prediction, in the header before any run, states per stage what must equal the stage's own
   through-harness run already graded (stage 1 PBS 788583, stage 2 PBS 788586, stage 3 PBS 788587 when it lands, stage 4
   W036's job) and names every difference by cause before it is seen: scAnno now receives `--assay snrna` where the
   promoted record has `sn`; stage 2 now runs `embed`, so its joint object is compared with the promoted one. Submit
   recipe between `# SUBMIT-BEGIN` and `# SUBMIT-END`; a final `GATE:` line.

composed `pbs:` block (`$SCH_SITE/stack.yml`, then the project's `stack.yml`; `compose` merges mappings), and already lays

**The changes, in the order the brief sets.**
1. **(2) GAP-C91, each stage's cost.** The pbs handle keeps the scheduler's last word on the job and, once the job has
   ended (`wait` or a confirmed `stop`), records `facts.cost`: `from: scheduler`, the job, `wall_s` and `peak_mem_kb`

   the scheduler said nothing after the end (no job history, or the seal ended it), `from: null` and the reason. The local
   handle records `wall_s` from its own clock and says peak memory is not measured (it asks no scheduler). The kernel
   appends one `run/cost` event per run (method, probe, gate, companion), and the report gains `cost`: the stage's
   `cells` (counted on its observations, with its event), `wall_s` (the sum) and `peak_mem_kb` (the maximum), each value
   with the event numbers it came from (P2), and the runs it could not measure, by name. The stand-in scheduler prints
   `resources_used.*` for an ended job as PBS Pro words them.

   scQC's own `sample`). The driver writes the request's `keys.sample` into each declared path whose command is declared,

   scAnno's `embed` then writes the cohort's column into the joint object, so stages 3 and 4 read it by that name.
3. **(1) The cluster path.** Where resources are declared: the SITE file holds the queues, each with its ceilings
   (`pbs.queues`, read from the site's own queue table), and the defaults; the REQUEST holds the cohort's sizes per stage
   and for the driver (`resources: {drive|<stage>: {ncpus, mem, walltime}}`; a queue there is refused: it is the site's);
   a TOOL's plugin.yml may declare `resources:` as its default, under the request (none of the four declares one: no
   measured value exists to declare, and none is invented). The driver writes a stage's sizes into its stack as
   `pbs.plugins.<plugin>` (so only the stage's own run takes them; its probes, gates and companion keep the site's
   default), and the executor composes `select=1:ncpus=N:mem=M` from them and picks the FIRST declared queue whose
   ceilings fit (LAYOUT 3h: the queue from the requirement); a requirement no queue fits is refused before any qsub,
   naming the ceilings. `sch run --request R --out RUNDIR --answer ... --by WHO --job FILE` writes, instead of running,
   the job that runs that same command on the cluster: its `#PBS` block from the site file and `resources.drive`, its
   environment from the site file (`job:` block: the harness checkout, the kernel's interpreter, any `module`/setup

4. **(4) The first cohort's request and chained job,** in the cohort's folder (`stages/00_driver/`): `request.yml` (every
