# W048 (QC): scQC is leak-clean under the cohorts' generated lists, and the fixture's axes reach its pipeline

**Registered** 2026-11-11 by the coordinator, before any code or number. ROUTE item R13, run 2 (run 1 was W043, merged
at `de62f78`). **Gaps** GAP-C78, and scQC's part of GAP-C26 and GAP-023. **Goals** A3.1, QC.1. **Repository**
github.com/JiaenLin/scQC, branch `autodev/W048-leak-clean`, from `main` (`de62f78`).

## Why
A3.1 is 0.41, under the bar of 0.5. Half of it is the leak-and-fixture half: a tool counts when it is leak-clean under
each cohort's generated term and shape lists AND the two-shape fixture's axes reach its pipeline. scAnno counts since
2026-11-11. scQC does not: under the generated lists its own text holds more than two hundred hits (GAP-C78 counted 218
on the main line), and its own guard reads the lists' `word:` and `exact:` lines as literal text, so it checked only the
carried terms.

## The change
1. **The guard first.** scQC's own leak guard reads the generated lists' syntax (`word:`, `exact:`, shapes) the way the
   harness's conform does, so that it fails today for the reason that is true. That failing guard is the test that fails
   on the base.
2. **Every hit in scQC's own files goes, its fact stays.** A cohort's sample name, count, path or run key leaves the
   tool; what the sentence said about the METHOD stays, restated without the cohort (a number that is one cohort's
   measurement goes to the cohort's record, not into the tool; ATTACKS 16). No excuse is added to any scope list, and no
   term is removed from a list. A record the tool writes (design files, history, ledgers it generates) is scanned too
   (ATTACKS 5).
3. **The fixture's axes reach the pipeline.** `sch dev check --only fixture_a` runs scQC's real CLI on the two-shape
   fixture past `describe`: the value axes (assay cell and nucleus; the design's factors) reach the steps that read
   them, and the check fails if one does not.
4. **Not in this run** (run 3, same repository, registered when this one hands back): GAP-C104, scQC's silent
   acceptance of single cells that another tool denoised becomes an asked, recorded decision (D-031).

## Acceptance check
- The harness's conform `leak_scan`, untruncated, with each cohort's own terms and shapes, one cohort at a time: 0 hits
  in scQC's files for each cohort; scope excuses unchanged; scQC's own guard agrees with it on the base (red) and on the
  head (green).
- `sch dev check --only fixture_a` on the clone: every tier green, and a deliberately broken axis makes it red.
- scQC's suite green with a shadowing `tests` package present. Rule 2: no assay rule is touched.
- If a file a promoted job executes changed: both cohorts' promoted stage-1 runs reproduce IDENTICAL at the head (dated,
  re-pinned copies of W043's two reproduction jobs, each asking the time its last run measured, with a margin).
