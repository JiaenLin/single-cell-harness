## Why
The driver's two fix rounds closed five of the first verifier's six reasons by their principles. Its last re-check
failed on one: a file given as the ANSWER to a decision is read by a tool and is in no pinned set, so a resume, a plan
check and a generated job all pass after that file is edited, and a job's gate line can read as predicted on thresholds
its prediction was not written for. The rule of two fix rounds turns the residue into gaps and this wave, as W047 did
for W035; one verification of the whole driver batch follows it.

## The change
1. **Every file a tool is handed is in the one set (GAP-C110).** An answer whose value is a path enters `run_inputs` and
   the job's pins exactly as a path param does: at the plan, at each stage's start and seal, on every resume, at
   generation. The principle, not the one case: list every route by which a path reaches a tool's argv (the request's
   params, an answer, a decisions file, a site file, an adapter's own default) and show each is in the set or refused.
   The re-checker's two limits of the same family are closed or refused by name: files under a symlinked subdirectory of
   a named directory, and a path-valued answer given relative.
2. **Correct requests plan (GAP-C111; ATTACKS 10).** Since fix round 2 the profile refuses aligners and upstream tools
   that real, correct requests name (for nuclei: a multiome aligner, a second ambient remover the base accepted; for
   cells: three common aligners), and a word param is refused as "a relative path" when a folder of that name happens to
   sit beside the request. What may run upstream of an assay is what the stage-1 tool itself accepts for that assay,
   compared with the tool's own declaration by a drift test, never a hand list that is stricter or laxer than the tool.
   Rule 2 does not move: the family never runs a nucleus-calibrated ambient remover on single cells, and single cells
   that arrive already denoised stop at the named decision (D-031), whatever stage the request starts at (the re-checker
   found a request starting at stage 2 plans without reading the sheet's ambient columns).
3. **Small, same files:** a decision answered with a blank name is refused; a size value holding a newline is refused;
   the stand-in of scQC refuses what scQC refuses for a supplied ambient file without its provenance fields (ATTACKS 1).
4. **Not in this wave:** the scIntegrate adapter's state version and its stand-in's key column (GAP-C109: they land with
   scIntegrate's batch, D-034); the late refusal of an unknown stage-4 flag (cost only, no result); bringing W045 onto
   the driver (its own run).
