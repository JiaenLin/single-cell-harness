# W052 (HARN): the harness reads scIntegrate at state version 2, and its stand-in behaves as the tool

**Registered** 2026-11-11 by the coordinator, before any code. ROUTE item R20's harness side (GAP-C109), on the PI's
ruling of the same day: "do not block anything if unnecessary" (D-041). **Goals** A1.1, A1.2, INT.1, and A3.1 through
scIntegrate's merge. **Repository** the harness, branch `autodev/W052-int-state2`, from `main` (NOT from the held driver
branch: this must merge on its own).

## Why
scIntegrate's batch (W039: withheld cells out of the PCA; W046 with its fix round 1: the design's key column kept,
names checked before anything runs) is verified PASS at `2fc7a6c` and declares state version 2, as the state contract
requires when a tool's numbers move. The harness's adapter still means version 1, and refuses that head by name. So
neither can merge alone. What held the pair until today was the tool's fresh-environment job, which found a defect of
the installer that is on `main` too (GAP-C116): that defect gets its own follow-up and no longer holds the merge.

## The change
1. The `int@scintegrate` adapter and its declaration mean state version 2 (the adapter's constant, the declaration's two
   lines), and the mismatch test's literal moves to another number.
2. The harness's stand-in of scIntegrate behaves as the tool does at `2fc7a6c` (ATTACKS 1): it keeps the design's key
   column under the design's own name, refuses a conflicting column and a name the writer forbids, writes `design_key`
   into its report, and declares version 2.
3. The first cohort's stage 3 through the harness, as the pair's gate: a dated copy of the through-harness stage-3 job,
   pinned at this branch's head and at scIntegrate `2fc7a6c`, with its prediction written against W039's own run (the
   embeddings moved there by design; the promoted run is no longer the reference for them) and against the previous
   through-harness run for everything W039 does not touch.

## Acceptance check
- The harness's test of the real tool: scIntegrate at `2fc7a6c` mounts and unmounts; scIntegrate at its old `main`
  is refused by name (the mirror of today's refusal). The suite green; conform no new hit.
- The stand-in's new behaviour has tests that fail on `main` for the stated reasons.
- The job reads AS PREDICTED at both heads; then both `main`s move in one step, the tool first.

## Prediction
A3.1 +0.1 when the pair merges (scIntegrate's credit, judged yes by its re-checker). A1.1's count does not move: the
first cohort's stage 3 through the harness already counts, and this run renews it at the new heads.
