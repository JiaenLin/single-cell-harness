# W053: the Studio writes a bound as the p-value of genes it did not test

Lane PLAT. Repository scrnaseq-studio, base `192057b` (main, deployed), branch `autodev/W053-untested-genes`.
Found by the W051 words-pass review (its limits 1 to 3 and the doc line of limit 6).

## Builder's plan

Written before any code.

**Defect 1, the wrong number.** `saturated` in `src/lib/significance.ts` is `!(p >= 1e-308)`, so a NaN counts as
an underflow; an untested gene (kept under `logfc.threshold`, `p = padj = fdr = nlp = NaN`, `stats.ts` `carry`) is
written `<1e-308` in the DE CSV and `NaN` in `neg_log10_padj`. Change: one rule in significance.ts for "absent"
(not a finite number) ahead of "saturated" (a real p under 1e-308, 0 included). Absent is an empty cell in a CSV
and the em dash on screen (the standard's one meaning of the em dash: no value in a table cell). The DE CSV gets
a last column, `not_tested`, empty for a tested gene and the screen's words for one that was not ("under
logfc.threshold: kept, but not tested"). The CSV's rows are built by a pure function (moved out of the component)
so the test can read exactly what the file holds; the volcano's point set is taken by one exported filter. Every
caller of `saturated`, `pTxt`, `pCsv`, `nlpTxt`, `nlpCsv` and every place a NaN p can reach is listed in "As
built" with before and after.

**Defect 2, the wrong line.** Under the FDR cutoff the volcano's y axis and its dashed line are Bonferroni while
the larger points are FDR, and a BH boundary is not a line on a Bonferroni axis (a gene can pass FDR with padj
clamped at 1). Change: the y axis is the correction the cutoff is read off. Under FDR it is −log₁₀ FDR, computed
in log space by `finish` beside `fdr` (the same step-up, so it agrees with the column by construction and keeps
resolution where FDR underflows), carried across the worker; the dashed line is at the FDR cutoff, the axis
title, the readout, the screen's line and the saved legend say FDR. Under Bonferroni nothing changes.

**Defect 3, the raw number.** The slider sets the cutoff to 10^-v, and the head, Methods, the saved legend, the
table's chip tooltip and Enrichment's empty state print it raw. Change: one formatter for a cutoff, by the
standard's numbers table (p: two significant digits; under 0.001 as 1.4e-5), used everywhere a cutoff is shown
or saved; and the cutoff in force is the number written (the slider's value is rounded to two significant digits
when it is set), because a written 0.32 over a cut at 0.3162 would misstate which genes pass. Where a cutoff is
named its correction is named with it (the chip tooltip and Enrichment's empty state said "padj" under FDR).

**Doc.** README: a short "Changed in this version" note naming the three renamed saved names.

**Acceptance.** `npm test` grows by a check per defect, each failing on `192057b` for the stated reason: (1) no
untested gene carries a p, padj, FDR, −log₁₀ padj or a significant rank in the table model, the CSV rows or the
volcano's points, and a real underflowed p (0, and 1e-320) still writes the bound; (2) under FDR the volcano's y
for each tested gene is −log₁₀ of its FDR, the larger points are exactly those above the dashed line and past the
fold-change lines; (3) the cutoff is written in the standard's form everywhere and the value in force equals it.
`npm run test:export` extended to save a DE CSV with Seurat's defaults on. Must not change: every number of a
tested gene (DE table and CSV with no threshold, and the tested rows with one, compared before and after, digit
for digit), the Run card, the wording check, every existing check (1,999 ok at the base; export test 556 of 556).

**Prediction.** At the base the reproduction shows 58 of 70 rows with `<1e-308` and no p on screen; the lab volcano
under FDR 0.316 has its dashed line at y for padj 0.316 with both large points on or below it; the head reads
`FDR < 0.31622776601683794`. At the head: 0 untested rows with a p; both large points above the line; `FDR < 0.32`.
