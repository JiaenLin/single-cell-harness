# W057 (PLAT): the Studio's Run card says what a bundle holds, for old and new bundles; a ragged table is refused

**Registered** 2026-11-12 by the coordinator, before any change. ROUTE items R38 (what is left of it on the Studio's
side) and R48 (GAP-C117's Studio half). **Goals** PLAT.2, A6.2 (no score moves). **Repository** scrnaseq-studio, branch
`autodev/W057-run-card-words`, from `main` (`8fb0d0a`, deployed). **Designed and built by a Fable designer** (D-026:
every UI is designed by one); then one independent check; then its deploy (D-045).

## Why
Lab's converter changed what a bundle's run section holds (W054, live at Lab `fdb8888`): six named short strings per
record (tool, version, commit, run key, stage, job) from the first 64 records, never the record itself. The Studio's
Run card still speaks of the older design. Two verifiers read every sentence against what bundles hold:
- "left out of this bundle over its budget" is said of a record left out after an over-long value: the reason is false;
- "the converter found none where it looked" is said when the only candidate could not be inspected: the note beside
  it says the converter cannot tell;
- "copied" and "as the lab's converter carried them" describe whole records; a developer document lists three forms of
  a record that the lab no longer writes.
Bundles written by earlier versions of the lab are on users' disks and must stay described truly.
Separately (GAP-C117, on `main` since before these waves): a table whose header is not as wide as its rows is offered
with every later column carrying its neighbour's counts and no note.

## The change
1. Every sentence the Run card, the Methods tab and the bundle document can say about run records is true for a bundle
   written by the lab today AND for one written before W054. A sentence states no reason the bundle itself does not
   state; where the bundle's notes say why, the card points at them. "None listed" and "could not look" are not given
   the same words unless the words are true of both.
2. The words follow the Studio's own written standard (W051: word budgets, one term per concept).
3. A table whose header is not as wide as its rows is refused with a message a user can act on, never offered.

## Acceptance check
- A truth table: every state of a bundle's run section (none; wrong shape; no record listed, none found; no record
  listed, some found; records listed; records listed and some left out by the cap, and by a long value; six empty
  fields), each as a new bundle and as an old one, opened in the built Studio: every sentence TRUE, 0 page errors; a
  test per row.
- The ragged table: refused by name, with a test that fails on `main`; a well-formed table unmoved.
- Suite, lint and build green; nothing else on any tab moves (screens compared before and after on one ordinary bundle).

## Prediction
No score moves. Two known false or imprecise sentences on the live pair end; one wrong table stops being shown.

## Designer's plan (2026-11-12, before any change)
Read first: the Studio at `8fb0d0a` (the card, its reader, Methods, the bundle document, the README, the written
standard and its check), Lab's writer at `fdb8888` and at `ca0cc73`, W054's fix round 2 and both verifiers' notes.

**What a bundle can tell the Studio.** The run section has the same top shape at both Lab commits (`searched`,
`records` of a path and a record, an optional `leftOut` of a count and paths); `searched` is the same sentence at
both; the bundle's `schema` did not change; there is no version field. So a bundle is told apart **by the fields
present, record by record**: today's Lab writes a record only as a dict of one to six of `tool`, `version`,
`commit`, `stage`, `run_key`, `job`, each a string (the *six-field form*); a record in any other form (a dict with
another key or a value that is not a string, an empty dict, a "(not copied: …)" sentence, null, a text, a list or
number) was written by an earlier converter. A section holding at least one record of another form is placed as
the earlier form and described as it is today. **A section the fields cannot place** (no record listed; or every
record in the six-field form, which an older bundle of small records also is) gets only words true of both; the
Studio never guesses, and reads no prose of the notes to decide a fact. Rejected: placing a bundle by matching the
converter's note sentences (prose that Lab may reword; a wrong match would state a false fact).

**Every place the Studio speaks of run records** (found by reading; no tooltip does today):
1. Overview's Run card (`RunCard.tsx`) and its reader (`lib/run.ts`): the table below.
2. Methods (`Methods.tsx`): two sentences, below.
3. Overview's notes card ("From the conversion"): the bundle's own notes, shown as written; unchanged.
4. One note the Studio writes for a collection whose parts differ ("part(s) … carry a different run section from
   part K; the run shown is part K's"): true of both forms; unchanged.
5. The bundle document (`tools/BUNDLE.md`, "The run that produced the object"), the README's "The run." paragraph,
   and the comments that describe the form (`lib/bundle.ts`, `lib/source.ts`, `lib/run.ts`, the fixtures' README):
   rewritten to say what Lab writes now, what older bundles hold, and how the two are told apart.
6. The generated copy deck and its inventory: re-measured.

**Methods.** With a record whose content is in the bundle, earlier form: "This text reads nothing between the counts
and those labels: the object carries the run's own record(s) (paths), which Overview shows as recorded, and how many
variable genes were kept … are not read out of it/them here, and are not guessed at." unchanged; and "because it
reads none of them out of the run's records" unchanged. Six-field section: "… the bundle lists the run's record(s)
(paths) by up to six named fields, which Overview shows, and how many variable genes were kept, how many components
were used, how large the neighbourhood was and at what resolution the graph was cut are not among them, and are not
guessed at." (59 / 200), and "because the fields this bundle lists of the run's records hold none of them". With no
such record: unchanged.

**Terms.** A *run record* is the object's (an entry of its uns); a record is *listed* when the bundle's run section
has an entry for it; *copied* stays only for an earlier converter's whole copy. "Identity" is a retired word in the
standard, so the six are called fields and named. Rejected: one badge "named fields" for every six-field record (it
does not say how many of the six the bundle holds, which is the one thing a reader counts).

**The ragged table.** Readers found: `parsePseudobulk` (`lib/bundle.ts`, one bundle) and `mergePseudobulk`
(`lib/collection-source.ts`, a collection's parts, also the path of a large object read in parts). No other table
is read from a bundle (the gene lists are one column; the gene-set library is the app's own file). Both get one
check before any header is read: every line has as many columns as the header. A table that fails is not offered,
raw counts read as absent, and a note says (the voice of the notes beside it; 31 and 28 words of 40): "the summed
raw counts are not offered: line L of pseudobulk.tsv has G columns and its header has H. The sample "a\tb" holds a
tab, which splits a column in two: rename it in the object and convert again" when a sample or cell type name the
bundle declares holds a tab (the cause is then read from the bundle, not guessed), and otherwise "… has H, so no
count can be matched to its column. Convert the object again". In a collection the table is named with its part.
Rejected: repairing the header by joining cells back (a guess at which cells belong together).

**Proof planned.** Each state as a new bundle (Lab `fdb8888`) and as an old one (the same object at `ca0cc73`),
converted here from the verifiers' objects and re-digested against theirs before reuse, opened in the built Studio
headlessly; the run sections and notes of those bundles committed as fixtures, one test per row; the ragged table's
tests; the screens of one ordinary bundle before and after; the copy inventory re-measured.
