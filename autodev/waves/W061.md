## What was measured
The first cohort's real joint object (about 3.2 GB, written by the integration tool at its `main` through the harness)
converts with the lab's documented command, no flag and no manual step, and the bundle equals the object in every
value compared; the Studio opens it with no page error. That half of A6.2 is YES. But on this real object the live
pair tells a user things that are FALSE, and the run is not shown:
1. **The integration method is guessed from a name.** The Studio says "Batch integration: harmony" and its Methods text
   says the data were "corrected with harmony, as recorded in the object", with that method's citation. The object
   records another method, and the embedding that opens is that other method's. The lab decides "harmony" when any
   embedding's name holds the word. A user can paste a false methods sentence into a paper.
2. **Raw counts are dropped without a word.** The object holds a counts layer; for an object large enough to be split
   into parts the lab leaves the counts out with no note; the Studio then says "Raw counts: not found", disables the
   pseudobulk export, and elsewhere still says the pseudobulk counts can be saved.
3. **"Total counts" is not counts.** The per-cell QC total is summed from the log-normalised matrix and drawn under the
   label "Total counts".
4. **The lab's own page promises what does not happen** before converting ("Pseudobulk DESeq2: yes", "All 11 travel
   in the file" where 5 travel), and a count of grey cells includes cells with no coordinates.
5. **The run is not shown.** The card lists the producing tool's record by tool, version and commit (each true); the
   job is recorded as a group and is not carried, and no run key, stage, date or input is recorded as a field. A user
   can tell which code made the object and not which run. (This is the test's second half: PARTLY.)

## The question the design must answer
Which facts about an object may the lab STATE, and where must each come from: a fact the object records (then it is
read from a named place, and "as recorded in the object" is true), a fact the lab measures from the values (then it
is said as measured, with how), or a fact nobody recorded (then it is said as not recorded, and never guessed from a
name). And for the run: which writer records the run's identity (a run key, a stage, a job, a date) as fields the
lab's closed reader already carries, so that the second half of A6.2 becomes YES without the lab reading anything new.
Answered wrongly, the next real object brings the next false sentence.

## What the design carries (item 21a)
The problem from the root; THE CLASS (every statement the lab or the Studio makes about an object: the closed list,
each with its source kind: recorded, measured, not recorded; the one place that defines it; the one test that walks
it); the design by construction; one other design and what it gives up; the build as waves of at most three numbered
changes each, per repository, in order, with each wave's acceptance check and the rows its proof table must hold
(the real object's shapes rebuilt as SYNTHETIC fixtures: no cohort value in any repository); what moves A6.2 to 2 of 2
and by which run; the attacks the builders must run; what the design gives up.

### 3. The design by construction
One optional member of `meta` in bundle@1 (an old reader ignores it, as it ignores `run`: `L:lib/build.ts:158`):
```
meta.facts = { v: 1, <id>: Fact }                               absent in a legacy bundle
Fact = { kind: 'recorded', value: string, at: string }           read from that place, verbatim
     | { kind: 'recorded', value: null,   searched: string }     said as "not recorded", with where the lab looked
     | { kind: 'measured', value, of: string, how: string }      of = the matrix or embedding measured
     | { kind: 'chosen',   value: string | null, by: 'flag' | 'guess' | 'app' }
```
- **Recorded.** Read by key from a named place, never found by a pattern over names; carried when a scalar string of 64 characters or fewer, else named in a note and not carried (the run reader's refusals: `L:lib/h5ad.ts:909-928, 990-1004`). An absent place gives null, and nothing fills a null. Only this kind, with its `at`, is worded "as recorded" or badged "from your file", the place printed beside it.
- **Measured.** Said as measured, with `of` and `how`. A total is called counts only when `of` is a matrix whose stored values were measured as integers; a sum of log-normalised values is titled so. Row 5 measures the per-cell total too (expm1 row sums of up to 2,000 cells spread over the object): "log1p of counts scaled to N per cell" only when every sampled sum is within 0.1% of one N; else "log-normalised, no constant per-cell total". Row 18 runs over every name and carries the count; row 17 is counted per carried embedding.
- **Chosen.** A role is a parameter of the conversion, not a fact of the object: the column and `by`. The Studio says "chosen at conversion", and of `guess`, "the command's guess from the column's name". No citation is attached to a column's or an embedding's name (rows 12 and 13 end).
- **Dropped.** `facts.counts` is measured on the WHOLE object before any split, and when true requires `carried` and `why`. First SAID: in the notes of the collection and of every part, and where the Studio said "absent": "in your object at `layers["counts"]`; not in this bundle: (why)"; rows 7 and 20 read `carried`. Then CARRIED (wave L2): a second pass over the counts matrix, read by rows and never held, gives each part its sample by cell type sums (the per-part table the Studio already merges: `S:lib/collection-source.ts:439,730`) and the per-cell totals OF COUNTS. Where it cannot (a column-major matrix, another gene list, a non-integer met while reading), `carried` is false with that reason.
- **The integration method.** One place, read by key and naming no tool, as the run reader names none (`L:lib/h5ad.ts:854`): a dict directly under `uns` that holds `default_method` as such a string, `default_embedding` beside it. The family's writer writes both today (`T:emit.py:238-239`), so the object already measured reads true with no rerun. No community key records a method: other writers leave only an embedding's name, and scanpy's `uns/neighbors/params/use_rep` names the representation a graph was built on (from memory, not verified, not read in this wave); a foreign object says "not recorded". The words are "The object records its integration method as `m` (the place) and that method's embedding as `X_m`", never "was corrected with": the value can be the tool's "none" or "none chosen", shown verbatim. A citation only when the value EQUALS a key of the Studio's closed table. Several corrected embeddings are listed as the object's keys under "a name is not a record of what was run"; of the one that opens, only the measured relation the lab already has ("the same coordinates as", `L:lib/build.ts:674-676`). Two dicts with a `default_method`: both, each with its place. A `default_embedding` that is no obsm key is said so.
- **Not stated any more:** rows 3 and 4: nothing in the final object records them (the QC stage's record is not carried forward: GAP-P20), and "no column found" is a claim only a name search supports.
- **Before converting** (row 20) the lab's page prints only what `plan(scan, choices)` returns (split or not, the matrix read, counts carried, the embeddings carried by key); the command and the worker run that plan.
- **A legacy bundle** (no `meta.facts`) is worded as unsourced: "the converter wrote: (value); this bundle does not say where it read it": no "from your file", no "as recorded", no methods sentence, no citation.

### 5. One other design, and why not
**The lab keeps its guesses and labels each "inferred from a name".** One word a field, and something to say of a
foreign object. It gives up what this wave is for: on the real object the guess is not uncertain, it is wrong, and a
wrong method beside "inferred" is still a wrong method beside a citation; a label does not survive the copy of a
methods sentence into a paper; and the class stays open, the next name rule added as these were, with nothing to walk.

### 8. The attacks, and what the design gives up
- **Lab.** A name decoy for every row, and the pattern put back (the walk must fail). At the recorded place: a group, an array, a number, 10,000 characters, a line break, markup, `__proto__`, a link out of the file. Two dicts. A `default_embedding` the object lacks.
