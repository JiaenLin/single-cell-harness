## Why
On the family's real object the lab decides the integration method from an embedding's NAME and writes it into the
bundle with no source; the Studio then prints it as recorded, with a citation. The same guess is made for the
normalisation, the doublet and ambient tools, "principal components" and the cells not called. The lab's own page
promises before converting what the conversion then does not do ("Pseudobulk DESeq2: yes", "All 11 travel in the
file" where 5 travel), and an object split into parts loses its counts layer with no note.

## THE CLASS (from the design, section 2; the builder restates it against the code before any change)
Every statement the lab makes about an object, on its page or into a bundle, is one row of a closed table in ONE place,
and each row has a source kind that the type system will not let be omitted: RECORDED (read by key from a named place
in the object; absent place: "not recorded", never filled from a name), MEASURED (from values, naming the matrix and
how), CHOSEN (a decision of the conversion: by a flag, by the command's guess from a column's name, in the page: said
as chosen, by whom), or DROPPED (something the object holds that the bundle does not carry: said, with why). The ONE
test walks the table with a decoy for every row (a name that looks like a method, a tool, a normalisation: no row may
state it as recorded). The page before converting and the bundle after are built from the SAME plan, so the page
cannot promise what the build does not do.

## THE SIZE (three changes)
1. The facts table and its type in one module, the optional `meta.facts` written into a bundle in the shape W062's
   reader takes, and the walking test with its decoys.
2. Each of the lab's guesses becomes its row's true kind: the integration method and its embedding read from the keys
   the design names (an object that records none says "not recorded"; several corrected embeddings are listed as keys
   only); the normalisation, the doublet and ambient tools the same; a per-cell total is summed from counts or is not
   called counts; the cells not called and "drawn" said as what was measured.
3. One plan for the page and the build: every sentence the page shows before converting comes from the plan the build
   executes (what travels, whether raw counts will be in the bundle, whether pseudobulk will be possible); a split
   object's counts, not carried in this wave, are SAID as dropped in the notes and in `meta.facts` (carrying them is
   the design's wave L2).

### 2. Where the design, the Studio's reader and the lab's code disagree (the reader is the contract for shapes)
- **Ids and shapes** are the reader's (`S:lib/facts.ts:35-130`): 14 ids; `recorded` value at most 64 characters, one
  line, no `<` or `>`; a place at most 256; `how`/`why` at most 300; `measured` value a line, a number, a boolean or
  null; `counts` carries `carried` and `why`; `chosen.by` one of `flag`, `guess`, `app`. The lab refuses at run time
  what the reader would call unreadable, and says so in a note, so nothing the lab writes is drawn "unreadable".
- **Doublets and ambient.** The design (section 3) says "not stated"; its section 8, the registration and the brief say
  "not recorded" with the place. The lab writes RECORDED at a named place (`doublet_method`, `ambient_method` in a dict
  directly under `uns`, as `default_method` is for the integration), else `value: null` with that place as `searched`;
  the reader draws that "not recorded". No writer of the family writes those keys today (searched: none), so every
  object reads "not recorded", which is true.
- **The four legacy keys.** The design (L1.1) writes them null. The deployed Studio (`e475703`) reads only them and
  says "none recorded" of a null; null would make it FALSE on an object that records a method. The lab writes each
  legacy key as the recorded fact's VALUE when recorded, null otherwise; the W062 reader ignores the legacy key when
  the fact is present (`S:lib/facts.ts:147`). On the committed fixture this keeps `provenance` unchanged.
- **Two dicts recording a method.** The design says "both, each with its place"; the reader holds one value per id.
  The lab states neither (no `integration` fact, legacy null) and names each with its place in a note.
- **Split against whole.** The design's walk wants equal facts; in this wave a split does not carry counts, so
  `counts.carried`/`why`, `total.of` and `genes_detected.of` differ by construction (wave L2 makes them equal); every
  other fact is measured on the WHOLE object before the split and is equal.
- **How the split is forced.** The lab's tests force it in-process (`scripts/test-split.mjs` gives `chooseSplit` a
  synthetic count per cell; `scripts/test-integrity.mjs:214` builds parts with `shardScan`); nothing forces it through
  the command. The plan takes the threshold as a parameter (default `COMFORTABLE_NNZ`, `L:lib/shard.ts:23`); the
  proof's split fixture is converted by the command's own `convert` function with a lower threshold, from a script.
