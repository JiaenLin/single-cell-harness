# W065 (PROF): a plugin takes its allocation, not the machine

**Registered** 2026-11-12 by the coordinator, on the result of W055's gate job. **Gaps** GAP-C133, and the part of
GAP-C128 the job showed. **Goals** A4.1, A3.2 (through the merge of the scProfile batch), PROF.1. **Repository**

## Why
The dev suite ran on the cluster for the first time. Inside a job allowed 8 cores, on a node that has 256, the
differential-expression plugin's parallel library started workers for the whole machine on the suite's small fixture:
the first run was killed at its 32 GB request; the second, given 120 GB, used 63 GB, timed out after 20 minutes, and
its log ends in "Too many open files in system": a job of ours exhausted a shared node's open-file table. The first
cohort's stage 4 does not show it because that call passes a worker count; the suite's fixture run does not. The same
job showed that abundance's `agree` compares two monitoring fields of its own output, which differ from run to run.

## THE CLASS
Every channel by which a library inside a plugin's process decides how many workers or threads to start is set by
the HOST from the allocation it was given, before the plugin's code runs; a plugin that passes nothing gets the
allocation, never the machine. The ONE place that defines it: the environment the host builds for a plugin's process
(the builder names the function). The ONE test that walks it: a probe plugin, launched by the host with an allocation
of 2 on a machine made to report many cores, prints what each channel reads (the thread-pool variables, the parallel
library's own core count, the process's affinity if the host sets one): every one is the allocation; a new channel
added to the list needs no new test. Outside, counted: a plugin that asks its library for a number larger than its
allocation by hand (the maker's worksheet flags it; it is not prevented).

## THE SIZE (three changes)
1. The host's environment for a plugin's process, and the walking test with its probe.
2. Through the maker's verbs (a spent plugin is never edited by hand): abundance's declaration lists its monitoring
   fields as its execution record, so `agree` reports them and does not judge them; `agree` on the two-shape fixture
   has exactly the three figure-source lines of GAP-C128.
3. The gate job, predicted again from what PBS 792123 measured and what changes 1 and 2 do: `de` fixture and agree ok;
   abundance fixture ok, agree FAIL on exactly 3 lines; cellchat's fixture tiers FAIL with the measured count of
   instances (8 of 9 did not end ok on the cluster: say which one ends ok and why); a memory request from the measured
   peak of a run with the fix (on the workstation first), not a guess; its preflight gains one line: a probe of the
   allocation where the job runs.
