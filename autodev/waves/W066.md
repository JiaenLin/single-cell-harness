# W066 (HARN + PROF): the draw rule for never-seen tools, written before any draw

**Registered** 2026-11-12 by the coordinator. ROUTE item R36; design only for now (the direction review of 2026-11-12:
a design takes no Opus slot, and this one must exist BEFORE anyone learns which tools the maker handles well).
**Goals** A4.2 (0 of 5 today). **No repository is changed by this wave.** A Fable design agent writes the section
"Design" below (D4). The conversions themselves wait for the maker to be stable (the plugin line).

## Why
GOALS A4.2: published tools the family has never seen, drawn from the scRNA-tools catalogue by a rule written before
the draw, are converted by agents alone; each passes the dev suite and reproduces the tool's own published example
within a declared tolerance; the success rate and the time per conversion are reported. At least 4 of 5. Nothing of it
exists. A rule written after looking at what the maker converts well, or a draw redone until it suits, would make the
test mean nothing.

## The question the design must answer
The sampling frame and the exclusion rule, written before the draw, that keep five drawn tools convertible IN
PRINCIPLE (a published example on public data that fits the cluster's ordinary queues; installable from a public
source under a licence that allows it) WITHOUT fitting the rule to what the maker does well; how the draw is made so
it cannot be redone quietly (a seed fixed before the catalogue is read; the catalogue's snapshot hashed); what
"reproduces its published example within a declared tolerance" means for each KIND of output (a table of statistics, a
clustering, an embedding, a figure), declared before the conversion; what "by agents alone" allows and forbids; and
the pool's S and K (RULES item 16).

## What the design carries (item 21a)
THE CLASS (the closed list of reasons a drawn tool may be excluded, each checkable from public facts by someone who
has not tried to convert it; the one place the list lives; the one check that every exclusion names a reason from it);
the draw by construction; one other rule and what it gives up; the protocol of one conversion (what the agent is
given, what it may touch, what is graded, who grades, the tolerance note sealed before); the cost per tool; what the
design gives up.

## Design
Written 2026-11-12 by the design agent (Fable 5.2), read-only. No tool was ranked, looked up or named, and no draw was made. Citations: `G:` GOALS.md, `RT:` autodev/ROUTE.md, `RU:` autodev/RULES.md, `BR:` autodev/BRIEFS.md, `PF:` PLUGIN_FORMAT.md, other harness files by path; `P:` scProfile at `b5f646a`; `CAT:` the catalogue's public repository (`scRNA-tools/scRNA-tools`, branch `main`, folder `database/`), cited as `file:Field`. Read of the catalogue: its README, the header line of seven tables, `categories.tsv` whole, and twelve rows of each table with every name, title and address masked before display. **INF.** marks an inference. **C** marks a number that is this design's own, adjustable only before the rule commit (section 4).

### 1. The problem: five ways this test means nothing
A4.2 is a rate over five tools (`G:101`, `G:133`), and the family's own record calls a never-seen tool converted by a cold agent "the maker's only honest evidence that it generalises" (`docs/blind/README.md:3-7`). Each way below gives a number that looks the same.
- **(a) A frame fitted to the maker's strengths.** Here: keeping only the two kinds of upstream the maker's extractors read (`sch/dev/extract/python_package.py`, `r_namespace.py`); keeping categories like those of the nine plugins the family holds (`P:kernels/`); adding a "quality" filter once it is known which tools convert. Every filter not forced by the registration's words (lines 16-18 above) or by the plugin format is such a fit.
- **(b) A draw redone.** The catalogue is public today, so a seed typed into a commit can be tried in private first, ten seeds before one is committed. A second snapshot "because the first was stale" is the same act.
- **(c) Exclusions decided after trying.** "No runnable example" written after a conversion stalled; an exclusion by someone who can see that the next record is easier; a reason invented for one tool.
- **(d) A tolerance set after seeing the result.** The plugin's table differs in the third digit and the third digit becomes the tolerance; or the compared outputs shrink to those that matched.
- **(e) An agent helped by someone who knows the family.** A brief that says where the last conversion went wrong; a coordinator's sentence mid-run; the project's memory loaded into the session; a job file edited before it is submitted; conversion 1's transcript handed to conversion 2. The maker's rule is that a lesson reaches the next tool only through the maker (`RU:48`: "A maker fix found on one plugin is tested on the next").

### 2. The frame: a filter over the snapshot, computed from fields only
`setup/autodev/draw.py frame` (to be built; no judgement, no network) keeps a record of `tools.tsv` when ALL five hold:

| | in frame when | the field | why this and no more |
|---|---|---|---|
| F1 | the code location is an http(s) address | `CAT:tools.tsv:Code` | "installable from a public source" (line 18 above). Whether it still answers is a fact of a day, not a field: class E1 |
| F2 | a licence is recorded | `CAT:tools.tsv:License` is not `NA` and not empty | "under a licence that allows it" (line 18); a wrapping plugin MUST record the licence (`PF:403`). What the licence allows is read at the pinned release: class E4. The field's vocabulary was not read, so no list of "open" strings is written here: a list written blind would be edited after the snapshot |
| F3 | at least one publication that is not a preprint | a row of `CAT:doi-idx.tsv` (`Tool`, `DOI`) whose row in `CAT:references.tsv` has `Preprint` = FALSE and `arXiv` = FALSE | A4.3 and RULES item 18 need a peer-reviewed DOI with the title and year its own record gives (`G:102`, `RU:334-335`); `references.tsv` carries `Title` and `Date`. INF.: the two flags' meaning is read from their names and twelve rows |
| F4 | not only upstream of the matrix | not every `Category` of the record (`CAT:categories-idx.tsv`) has `Phase` = "Phase 1" in `CAT:categories.tsv` (alignment, assembly, UMIs, quantification) | a plugin's input is the profile's object, one observation per barcode (`docs/profiles/single-cell.md:14`), and the suite's fixture is 2,000 synthetic cells by 520 genes (`sch/dev/fixture.py:204`): a tool that only reads sequencing reads has nothing to run on in tiers T3 and T4 (`sch/dev/ladder.py:13-14`) |
| F5 | not held by the family | no identifier of the record (`Tool`; `CAT:repositories.tsv` `Bioc`, `CRAN`, `PyPI`, `Conda`, `GitHub`), case-folded with `-`, `_` and `.` removed, equals a package pinned in a lock or environment file, a `wraps.tool` value, or a tool named in `docs/blind/`, of the five family repositories at the commits the rule commit records | "tools the family has never seen" (`G:101`). The SEEN list is computed, never typed, and holds no candidate |

**No language rule.** The format runs a plugin as a subprocess it never imports, with plain JSON in and out (`PF:25-28`, `PF:265-266`); the entry point is `run.py`, `run.R` or any executable `run` (`PF:50`); the maker's layout is one Python file that declares the plugin (`PF:6-8`) and may drive another runtime, as the one R-backed plugin does (`P:kernels/*.draw.R`); the environment is a lock of exact pins from public channels (`PF:428-437`). So the format hosts any language whose runtime such a lock can pin, and `CAT:tools.tsv:Platform` excludes nothing. The one platform fact that excludes, a paid runtime, is a fact about a licence and sits in the class (E4). A record in a language neither extractor reads is IN, on purpose: it tests the maker where nothing has worked yet. `frame` prints into the pool's header the count of all records, the count each of F1 to F5 removes, and the in-frame count: that is where the fields' completeness is first measured (in the twelve masked rows `License` was `NA` in five, so INF. F2 removes a large share).

### 3. The class: seven reasons, one table, one check
A drawn record is ADMITTED unless a reason below holds. The list lives in ONE place, the table `CLASS` of `setup/autodev/draw.py`; a pool row may carry no other code. E1 to E5 and E6's first half are decided **by reading**: public pages only, no install, at most 40 tool calls in one session per record, by a cold reader told nothing of the family, the maker or any other position (its fixed brief is the class and the record's fields). E6's second half and E7 are decided **by the reference run** (section 5), at most three jobs. Neither is an attempt to convert.

| code | the reason | the evidence a row must hold |
|---|---|---|
| E1 GONE | the `Code` address and every package index that `repositories.tsv` names return no source on two requests at least 24 hours apart | both status lines with their times |
| E2 SEEN | the tool is one the family holds under another name, or its own documentation states that it is a wrapper, port or interface of one | the sentence quoted with its address; the family's lock line |
| E3 NO EXAMPLE | its authors published no example (vignette, tutorial, notebook, README code, or the paper's code repository) that names its commands and its data, with data that downloads without an account or a request, and with at least one output of section 5's four kinds | the places searched, a fixed list: the README; the folders for vignettes, tutorials, examples, notebooks and docs; the documentation site the README links; the paper's data and code availability statements |
| E4 NOT FREE | installing or running the example needs a credential, a registration, a paid licence or a paid runtime; or the licence at the pinned release forbids use by an academic institution | the sentence quoted with its address |
| E5 NOT A MATRIX | the example's input is reads, alignments or images, not observations by features with their annotations (`docs/profiles/single-cell.md:71-79`) | the example's data-loading line |
| E6 TOO LARGE | the authors state that the example needs a GPU or more than THE REQUEST; or the reference run, made as documented, is ended by the scheduler at THE REQUEST | the sentence; or the scheduler's own record |
| E7 DOES NOT RUN ALONE | installed as its authors document, at the pinned release, on a fresh prefix, the tool does not install or its example does not complete in three jobs: the documented route, then at most two changes, each a pin of one dependency to a version dated at or before the release | the three logs' last lines and hashes |

**THE REQUEST** (the stated number for "fits the ordinary queues"): one job of at most 8 cores, 64 GB and 2 hours of wall time, with no GPU. 8 cores and 2 hours are the family's own suite job (`jobs/dev_suite.pbs:4-5`; the blind job asks the same, `jobs/blind_convert.pbs:4-5`); above 2 hours a job owes a declared subset first (`RU:267-271`), and a published example has none. 64 GB is twice the suite job's 32 GB (**C**; the suite's own need is being measured again after a worker-count defect ended its first cluster run at 32 GB, `autodev/waves/W065.md:9-12`, `:31-34`; its fixture runs take 22 to 30 seconds a shape, `autodev/waves/W055.md:186-188`). No job file of the harness asks for a GPU (a search of `jobs/`). The queues' own maxima were not read: a job is never sized by them (`BR:93-94`).
**NOT a reason, ever:** the tool is hard; the maker has no verb, stage or extractor for its kind; its language is unusual but a lock can pin it; its output is random (section 5 measures that); it is unmaintained but installs; its dependencies clash with the family's (a plugin has its own environment, `PF:25-28`); the reader expects it to fail.
**Recording.** `draw.py next` prints ONE position, and only when every earlier position has a row in `autodev/pools/W066.tsv` (the pool's place, `BR:83`) at git HEAD: position, tool, verdict, code, evidence (address, date, quoted line, sha256 of the saved page), reader. One row per commit, made with `setup/autodev/commit.sh`. So an exclusion is committed before the next record is shown. Every EXCLUDED row is decided again by a second cold reader from fresh requests; where the two differ the record is ADMITTED. An exclusion needs two readers and an admission one, so a doubt costs the maker and never helps it.
**THE ONE CHECK**, `draw.py check`, walks the pool against git: (i) there is one rule commit, the snapshot commit is the one section 4 defines, and the snapshot's files hash to the recorded hashes; (ii) the frame and the order, recomputed, give the rows' tools at the rows' positions with no gap; (iii) every EXCLUDED row has a code of `CLASS`, the evidence that code requires, and a second reader's equal code; (iv) each row's commit is an ancestor of the next row's; (v) the grade of each admitted tool and the maker pair for the next (section 6) are committed before any row of a later position, and each tool's note, input and brief hashes before its conversion's first transcript record; (vi) at most five ADMITTED and at most 25 positions. It prints `DRAW: 5 admitted, <n> excluded, 0 unexplained` or `DRAW BROKEN: <the first row that fails>`. Before use it must print BROKEN on three doctored pools (a row out of order; an unknown code; one snapshot byte changed): a check that can fail, as `autodev/waves/W063.md:78` requires of a grader.

### 4. The draw, by construction
1. **The rule commit.** ONE commit adds `draw.py` (frame, `CLASS`, order, check), the empty pool with S and K, the three fixed briefs (reader, reference agent, converting agent) and the family commits F5 reads. It is pushed at once. No seed is typed anywhere.
2. **The snapshot is not chosen.** It is the FIRST commit on the catalogue's default branch whose committer date is later than the rule commit's. The coordinator fetches that commit's `database/` once and records its id and each file's sha256 in the pool's header.
3. **The seed is not chosen.** seed = sha256(rule commit id, newline, snapshot commit id). Its first half is committed before the snapshot exists, and its second half did not exist when the first was pushed, so no one can try seeds in private (way b): amending the rule commit before the snapshot exists changes an unknown, and a rule commit dated after the snapshot is refused by check (i). To redo the draw is to make a second rule commit and wait for the catalogue's next commit: two rule commits in history, which check (i) refuses.
4. **The order is fixed once and does not depend on the frame.** Every record of `tools.tsv`, in frame or not, gets the key sha256(seed, newline, `Tool`); the order is ascending key. The frame only filters. A repaired frame script therefore cannot reorder anything; it can only move named records in or out, and `check` prints that difference.
5. **The pool** is the first five in-frame records, in that order, that are not excluded. Positions are opened one at a time (section 3). The next position is opened only after the previous admitted tool is graded and the maker's commits for the next conversion are recorded (section 6), so nobody changes the maker knowing the next tool.
6. **S and K** (`RU:276-280`; `RT:84` gives S = 5). **S = 5**: five passes end the item at 5 of 5. **K = 5 rounds**: a round is ONE conversion of ONE untried tool, at the maker as every earlier trace left it (item 16's "evolved from every earlier trace plus at least one untried one"), and the fifth round ends the item whatever the count. Inside a round, item 16's subset is the workstation ladder and the gate's preflight before any real job, and "engineer" is at most 2 tuning passes by the same converting agent, then bad. **A failed conversion counts against 5 and is never replaced; only an excluded record is replaced, by the next position.** One more bound: 25 positions (**C**; five are found within 25 with probability 0.95 if one in-frame record in three is admissible and 0.79 if one in four: binomial arithmetic, the share itself unknown). At 25 with fewer than five admitted, the item returns to the route as a gap, "the frame does not find convertible tools", with the exclusions by code.
7. **A second pool is not a second chance.** If the item is registered again (item 16: "can be registered again"), it continues the SAME order from the next position, and every report gives the passes over ALL tools ever admitted. INF. (this design's reading; the score's denominator is fixed at 5 by the goals, `G:117-118`, and is the PI's): the score of record stays the first pool's, and "4 of 5" quoted from a later pool alone is way (b).

### 5. "Reproduces its published example within a declared tolerance"
**What is compared with what.** NOT the paper's printed numbers: those grade the tool's authors and the drift of its dependencies since printing, not the maker. The published example is taken as a PROCEDURE: the tool run alone as its authors document, at a pinned release (`PF:403-406` requires a pin; this design pins the latest release at the snapshot's date, or the default branch's commit at that date where there is no release), against the same tool run as the family's plugin on the same input. These are not the same numbers by construction: the plugin reads the input through the family's object and its declared keys, must keep the tool's recommended settings and mark every deviation (`PF:403-406`), and writes declared products. The first held-out migration found a plugin whose every fold change was negated on one of the two fixture shapes (`P:docs/MIGRATIONS.md:41`). The printed values are still recorded: an ANCHOR table (the example's printed value beside the reference run's) is reported per tool and not graded.
**Who, and before the conversion.** A REFERENCE agent, cold and never the converting agent, (1) installs the tool alone on the cluster and records the exact lock; (2) writes the example's input ONCE as the profile's object, as the example's own loading step yields it, and hashes it; (3) runs the example alone TWICE in identical jobs under THE REQUEST, seeded as documented (runs A and B), and a third time (C) if any compared output differs between A and B; (4) writes the note. The note has an OPEN half, the OUTPUT LIST: every table, labelling, embedding and figure the example shows, each given one kind below, its key columns and where the example shows it (an output of no kind is listed NOT COMPARED with the reason); the converting agent receives it. Its SEALED half (the reference outputs' hashes, the measured spreads, the tolerances by the rules below, the grading job) the converting agent never sees. The coordinator may add paths to the note, never a rule (`autodev/waves/W063.md:78`). The grading job must print `A42: REPRODUCED` on A against itself and `A42: NOT (n)` on a copy of A with one value, one label and one row changed. Then the hashes of the note, the job, the input and the brief are committed, before the launch. An edit of any of them after the launch voids the attempt. The notes hold site paths, so they stay with the runs; only hashes enter the records.
**The tolerance comes from the tool, by kind.** The references are A, B (and C); "identical" means A and B agree exactly.

| kind of output | the measure between two runs | pass when |
|---|---|---|
| a table of statistics (rows keyed by gene, cell, pair or set) | the overlap of the row keys; per numeric column, the largest absolute difference over shared rows; per ranked column, the rank correlation | references identical: the same keys, and every number equal to 6 significant digits (**C**, the one tolerance that is ours: the family's object may hold a matrix in single precision, INF.). Otherwise, on every measure: the plugin is as close to its nearest reference as the two farthest references are to each other |
| a clustering or labels (one per cell) | unnamed groups: the adjusted Rand index. Named labels: the share of cells with the same label. Also the number of groups | references identical: the same partition, or the same label on every cell. Otherwise: the plugin's best agreement with a reference is at least the worst agreement between two references |
| an embedding (cells by k) | coordinates are not compared between differing runs (rotations, reflections and random layouts move them): for each cell, the overlap of its k nearest neighbours in the two embeddings, averaged (k the example's own neighbour number, else 15, **C**) | references identical: the coordinates, as a table. Otherwise as for labels, on the mean overlap |
| a figure | no pixels: scProfile's docs record that label placement differs between two draws from identical inputs (`P:docs/TEST_LOOP.md:231`). The values the figure draws, taken from the plot object in the reference runs, are a table or an embedding; plus the counts: plot kind, the variable on each axis, the number of marks and groups | its drawn values pass as their kind and the counts are equal. A figure whose drawn values cannot be taken from the tool alone is listed NOT COMPARED |

With three references the rule "the nearest reference lies within the references' own widest gap" fails a plugin that is statistically just one more run about 1 time in 20 (INF.: 1 in C(6,3), if the six distances are exchangeable); with two references it would fail 1 time in 3, which is why differing runs get a third. **Two shapes.** The grader, not the agent, makes a second copy of the input with every role column renamed and the control's sort order changed, the two differences between the suite's own shapes (`sch/dev/ladder.py:14-16`). The plugin runs on both, both must pass, and the agent sees only the first. This is what catches a plugin written to the example's own column names in the case where the tool refuses the suite's fixture and the suite therefore proves little (`P:docs/MIGRATIONS.md:40`: "the plugin never ran").

### 6. One conversion's protocol
**The maker is pinned first.** Before a position is opened the coordinator commits the pair (harness commit, scProfile commit) that the conversion will use. **The pack** (a hashed manifest) holds: both trees at those commits, exported without history, which carry the maker's documentation and verbs as any user gets them (`skills/plugin-maker/SKILL.md`, `docs/DEVELOPING.md`, `P:docs/MAINTAINING_PLUGINS.md`, `P:DEVPOINTS.yaml`, the nine shipped plugins); the tool's public repository at the pinned release and its paper; the reference lock; the input object in its first shape; the OUTPUT LIST. **Withheld:** the program's records and memory, the pool's other rows, every earlier conversion's transcript, hand-back and blind record, the sealed half, the reference outputs, the second shape.
**The brief** is one fixed text for all five, in the rule commit, hashed; its slots are the tool's name, release and DOI and the pack's paths. It says: convert this tool into a plugin of this repository with the maker; you cannot reach the cluster; hand back job files and they will be run unchanged; the plugin must produce every item of the output list as a declared product; hand back `MAP.tsv` (output-list item, product, columns) and `DEFECTS.tsv` (one row per place where the maker, its documentation or the tool's documentation was wrong, missing or had no verb: the command, its output, what was done instead).
**What it may touch:** only its clean-room copy, and in it only what the maker's commands write for this one plugin and the answers they ask for (`skills/plugin-maker/SKILL.md:137`: "Never hand-edit any plugin"; `RU:48`). An edit of the host, the maker or another plugin fails the conversion; it is measured by a diff of both trees after the last turn, as the second blind record did (`docs/blind/0002-*.md:35`). A hand edit of its own plugin where no verb exists is a `DEFECTS.tsv` row and is counted.
**"By agents alone".** (1) The launch is a separate headless session whose working folder is the pack, outside the harness and the user's home, so that no project memory or instruction belongs to it, with the flags and the probe of `autodev/waves/W063.md:64-65`. Here the agent also has a shell, and the probe must show that the shell cannot fetch a public page or read a file of the harness (INF.: whether this machine's CLI can confine a shell so was not determined; if the probe fails, the agent gets no shell and every command is a job). (2) After the brief, every message to the agent is one of three FORMS with no free text: `RETURNED <job file> <folder>`, `REFUSED <job file>: <the gate's own line>`, `JOBS <n> of 6`. (3) The coordinator submits each handed-back job file unchanged (its md5 in the pool row) after the gate's preflight (`BR:84-89`) and copies the job's text outputs into the pack. (4) No person and no other agent edits anything in the pack. **THE CHECK over the saved transcript:** the tool list and working folder of its init record; the first message hashes to the brief; every later message matches a form; every path lies under the pack; every submitted job's md5 is that of a file the agent wrote. It prints `ALONE: <calls> calls, <jobs> jobs, 0 outside` or `NOT ALONE: <the first>`. NOT ALONE voids the attempt and the tool counts as failed: a voided attempt run again would be a second chance.
**The budget:** one agent session and at most 6 jobs: the environment; the maker's stages that need the tool's own interpreter (`jobs/blind_convert.pbs:17-20`); the suite's gate; the example on two shapes; and the 2 tuning passes of section 4. Conversions run one at a time; two at once only under one recorded maker pair (`skills/plugin-maker/SKILL.md:44-46`; the cap of two Opus agents, RULES item 21d).
**What is graded, and by whom.** A tool counts when four lines hold: `DRAW:` unbroken; `ALONE`; the suite's job for this plugin, written by the agent with the prediction "every tier of this plugin ok", prints `GATE: AS PREDICTED` on the cluster (the plugin's tiers as `autodev/waves/W055.md:173-176` runs them, and `sch conform` clean with the plugin in the tree, A4.1's words, `G:100`); `A42: REPRODUCED` on both shapes. A fixture tier that passed as a declared refusal is reported as such. The auditor, not the coordinator, writes the score from the four lines (`autodev/waves/W063.md:78`). **Reported per tool** (`G:101`: "Success rate and time per conversion"; the blind records' currency, `docs/blind/README.md:20-22`): wall time from the first to the last transcript record, tokens, tool calls, jobs and core-hours, the model, `DEFECTS.tsv` rows by kind, decisions that needed a person (must be 0), the reference agent's time beside it, the maker pair, the anchor table, and a blind record in `docs/blind/` whose predictions are written before the launch (`docs/blind/README.md:18-19`).
**A maker defect found during a conversion.** The agent records it and works around it inside its own plugin where the maker's commands allow (`docs/blind/0002-*.md:11-12`). The conversion is graded as it stands, at its pinned pair. Only after that grade is committed may the maker change, in an ordinary wave whose suite fails at the old commit; then the new pair is pinned, and only then is the next position opened. A failed tool is never graded again; it may be run again at the final maker and reported in a separate column, not counted. **What this does to the test's meaning:** the rate is that of a maker that moved during the test, each tool blind at its own pair. The report prints the pair per tool, and "4 of 5 by one maker" may be said only if the pair never changed. The order is computable by anyone who holds the seed, so "nobody knew the next tool" is kept by `draw.py next` and check (v), not by secrecy.

### 7. One other rule, and why not
**Draw from the whole catalogue with no frame and no exclusions, and count every record that cannot be converted as a failure.** It needs no class, no readers and no judgement, and its rate would speak for the whole of G4's population ("the 1,856 published tools", `G:42`). It gives up the test's subject. Most failures would be the catalogue's (no licence recorded, a preprint only, an address that is gone, an example on reads), so the rate would measure how the field keeps its software and not what the maker converts; and A4.2's "reproduces the tool's own published example" has no meaning for a tool that has none. This design keeps that rule's information without its confusion: the frame's counts and every exclusion by code are reported beside the rate. (Hand-picking five diverse tools gives up more: the picker knows the maker, which is way (a) entire. Strata by language or category need strata chosen by us, and five tools cannot fill them.)

### 8. The cost per tool, and what the design gives up
**Per position opened:** one cold read of at most 40 calls; for an exclusion, a second read; for E7, up to three jobs. **Per admitted tool:** the reference agent's run with 3 to 6 jobs under THE REQUEST (the install, A, B, sometimes C, up to two re-pins); the converting agent's run, the size the route calls M (`RT:84`), with at most 6 jobs; one grading job; the scripts `DRAW` and `ALONE`. About 3 agent runs and at most 13 jobs a tool. For five tools: 5 M runs, 5 reference runs and an unknown number of reads (INF.: 10 to 25 positions if between a half and a fifth of in-frame records are admissible). **Before the rule commit, one small build:** `draw.py` with its three doctored-pool cases, tried on a made-up catalogue that has the seven headers, never on the real one.
**What the design gives up.**
- **Five is five.** A maker whose true rate is 0.6 still shows at least 4 of 5 one time in three (0.34), and one at 0.8 misses it one time in four (0.26): arithmetic. The denominator is the goal's (`G:133`); no draw rule makes five tools say more.
- **The rate is about a sub-population:** tools with a recorded licence, a publication that is not a preprint, and a small public example that still runs alone. These are the better-kept tools. The frame's counts and the exclusions by code say how large the rest is; the rate says nothing about it.
- **The example is a procedure, not the paper's numbers.** A tool whose rerun no longer matches its printed values still counts if the plugin matches the rerun; the anchor table shows it.
- **The tool's install is solved by the reference agent, not the converting agent,** and its lock is handed over, so that a difference between plugin and reference is the wrapper's and not a dependency's. The conversion is not graded on solving the install; that time is reported beside it.
- **6 significant digits, k = 15, 64 GB and 25 positions are ours** (**C**), fixed in the rule commit.
- **Not prevented, only made visible:** computing the order outside `draw.py`; a rule commit backdated before an existing catalogue commit and never pushed (the push to the public remote is the witness; INF.: whether the remote keeps a push time was not checked); what the converting model already knows of a tool from its training.
- **Not determined here:** how complete any catalogue field is beyond twelve rows; the `License` and `Platform` vocabularies; the snapshot's record count; how often the catalogue commits (one push date was seen, the day before this design), and so how long step 2 of section 4 waits; where a job may fetch public data and packages on the cluster; whether a tool whose fixture run is a declared refusal should count on the suite's line (reported, left to the auditor).
